# 万物博物馆 V30.0｜万物联合展厅

**由两位真实馆长共同策划的展厅，需要双方同意才能公开。**

## 用户体验

V29 提供自愿跨馆会合；V30 在已接受、且双方公开展品仍然可见的 V29 会合上，允许创建一座**默认私密的联合展厅草稿**。

1. 一位参与者选择真实的 V29 双方会合，输入展厅主题和简介。
2. 两位馆长分别从**本人仍公开**的馆藏中贡献展品，写下本人的介绍理由；最多共 12 件，按加入先后构成展览路线。
3. 两位馆长需要**独立批准同一个修订版本**；至少双方各一件可访问展品。只有双份批准齐全，状态才变为公开，游客才可查看。
4. 任一馆长增加/移除本人展品、修改共同介绍、主动撤回批准，都会使公开展览回到草稿状态，旧批准同时失效，历史数字印章清空。
5. 游客可以沿展品顺序使用「🐒 双馆故事漫游」，逐站查看原始展品与**贡献者本人撰写**的策展说明。游客登录后可自行领取数字纪念章，也可撤回。
6. 任一位合作馆长可以永久结束这座联合展厅；关闭不删除原始馆藏，不影响私人 V27 星图或 V28 航线。

## 新奇互动

- **双人版本共审**：展品或文案有任何更新都会清除双方批准，避免馆长一方在另一方不知情时改写公开联合展览。
- **双馆故事漫游**：按两个真实馆长的加入顺序构成可逐站跳转的导览路线，不自动伪造知识链和因果关系；下一阶段可以扩展为双方独立排布的对照展。
- **数字观展纪念章**：每名登录用户每一版只可自愿领取一次；展示唯一账号印章数量，但不称为真实到访量。版本撤销时印章清空。
- **公开画廊**：游客看到的是真实双方审批、且所有来源仍然合法公开的联合展览，没有“AI 模拟其他馆长”。
- **公开分享入口**：链接可使用 `?coexhibition=<ID>` 打开相应联合展厅；未公开或撤回的展览对第三方始终不可见。

## 权限、来源与隐私

- 创建者必须是仍处于 `accepted` 状态的 V29 跨馆会合的双方之一，且两件会合锚定作品都必须仍然公开。
- 增加展品只能由该展品原作者本人执行，不得借用其他公开作品冒充自己的贡献。
- 撤下展品只能由贡献者本人执行；但双方均可撤回批准、结束合作。
- V30 **不会复制原始藏品的标题、描述、图片或标签**。展品仅保留来源 ID、贡献者 ID 和本人原创策展说明。
- 每次访问均验证原始展品仍为公开，以及所属玄幻世界、创作工坊和沙盒项目是否仍公开。任一原始展品或 V29 会合无效时，整个联合展厅退出公共发现列表，公开链接返回 404。
- 在成员预览中若有任一原始来源无效，隐藏联合展厅标题、介绍、旧展品名称和策展说明，只留下可辨认、可由贡献者删除的失效占位项。
- 共展览的原始藏品仍然由各自原作者控制；即使浏览者领取了纪念章，也不会反向赋予对私人源的访问权。

## 数据结构

`co_exhibitions`：V29 bridge ID（唯一）、联合主题、简介、修订号、两位馆长各自批准的修订号、`draft/public/closed` 状态、时间。仅在两个批准号等于当前版本时允许公开。

`co_exhibition_items`：展厅 ID、贡献者 ID、公开原展品外键（删除时置空）、策展理由、展示顺序。任何人不能修改他人贡献。

`co_exhibition_stamps`：展厅 ID、领取的登录用户 ID、领取时间。主键去重，版本更改、暂停公开和合作结束时清空。

## API

| Route | Description |
|---|---|
| `GET /api/coexhibitions/public` | 匿名可见的真实联展列表，实时核验 |
| `GET /api/coexhibitions/mine` | 我的联展、可创建的 V29 会合与我的公开原展品 |
| `POST /api/coexhibitions` | 创建默认私密草稿 |
| `GET /api/coexhibitions/{id}` | 参与者预览或已批准公开展览 |
| `PUT /api/coexhibitions/{id}` | 任一成员修改主题、简介并重置审批 |
| `POST /api/coexhibitions/{id}/items` | 仅添加本人公开藏品和原创说明 |
| `DELETE /api/coexhibitions/{id}/items/{item_id}` | 仅撤下本人贡献的展品 |
| `POST /api/coexhibitions/{id}/approve` | 双方分别批准当前版本；齐全才公开 |
| `POST /api/coexhibitions/{id}/retract` | 撤回全部批准并暂停公开 |
| `DELETE /api/coexhibitions/{id}` | 任一馆长关闭联合展厅 |
| `POST /api/coexhibitions/{id}/stamp` | 登录用户自行领取公开展览数字印章 |
| `DELETE /api/coexhibitions/{id}/stamp` | 撤销本人印章 |

## 实现与测试

- 后端 `coexhibitions.py`：复用 V29 `PUBLIC_SCOPE` 权限范围和跨馆会合。
- 前端 `static/coexhibitions.js` + `static/coexhibitions.css`：桌面与移动端导航、双馆工作台、展览路线、审批及印章。
- 测试 `tests/test_coexhibitions_v30.py`：授权建馆、双人共同批准、版本修订、用户互不篡改、印章唯一、撤回来源保护、会合关闭、真实公开画廊、接口校验。

**尚未验证**：生产真实浏览器视觉回归、连续点击交互可用性、大规模并发及刷章防护；当前功能适合自托管原型验证，不能宣称面向无限用户的生产级集群能力。
