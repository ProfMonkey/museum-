# 万物博物馆 V15.0：跨馆真实馆藏路线

## 设计目标

让「科技史、自然史与人类文明」从独立搜索栏目变成能够沿路线浏览的真实馆藏。**每个搜索结果必须来自机构官方接口**，策展路线仅表示值得比较的研究话题，不宣称两件对象存在历史因果。用户公开投稿、机构目录与个人私密收藏保持独立。

## 接口与数据来源

| 来源 | 搜索入口 | 主要对象 | 媒体策略 |
|---|---|---|---|
| 大都会艺术博物馆 | `/api/world-sources/search?provider=met` | 古董、古画、珠宝、器物 | 仅馆方确认公共领域才展示图像 |
| 伦敦自然历史博物馆 | `/api/world-sources/search?provider=nhm` | 标本、昆虫、矿物、化石 | 采集年份不等于地质年龄，图片另行核验 |
| 美国国会图书馆（新增） | `/api/expeditions/search?provider=loc` | 历史照片、早期计算机、电报与工业档案 | 每条权利不同，默认只显示文字 |
| NASA 图片影像库（新增） | `/api/expeditions/search?provider=nasa` | 天文、地球观测、航天器 | NASA 媒体一般可用于教育，但第三方内容例外；当前未逐图展示 |

美国国会图书馆 JSON API 免密钥，但官方说明限制请求频率（20/分钟）；NASA 图片库为独立于 NASA 开放数据门户的搜索 API。API 不可用时展示明确错误与机构链接，不伪造条目。

### V15 后端接口

- `GET /api/expeditions/catalog`：六条策展路线及固定馆方关键词。
- `GET /api/expeditions/search?provider=nasa|loc&q=...&limit=6`：每次最多 6 件可信来源目录结果，限制关键词长度 2–60。
- `POST /api/expeditions/save`（需登录）：仅支持此前由服务器从官方 API 搜索并缓存的 `record_id`，无任意 URL 注入；自动生成个人私密展品，并对账号 + 来源链接去重。

## 六条路线

1. 从盔甲到航天器：大都会铠甲 → 国会图书馆工业设备 → NASA 航天器。
2. 从古画到太空摄影：大都会风景绘画 → 国会图书馆航空摄影 → NASA 地球影像。
3. 从化石到生命星球：NHM 化石 → NHM 蝴蝶 → NASA 地球科学。
4. 电报、计算机与深空通信：LoC 电报 → LoC 早期计算机 → NASA 深空网络。
5. 从水晶到空间望远镜：NHM 石英 → LoC 光学设备 → NASA JWST。
6. 从航海地图到月球地图：LoC 航海图 → LoC 天文观测 → NASA 月球测绘。

各站是检索提示词；实际展示的作品和条数以馆方返回结果为准，可能为空。

## 年代与许可

- NASA `date_created` 是档案所记录的媒体日期，不代表技术发明时间。
- LoC 的 `date` 若精确到年份，只能据其所在大区间分类；不知道月日时不会草率归入「最近一年」。有歧义的年代保留「时间不详」。
- 无任何可用数据时不会制造“亿年前”化石的虚假馆藏。
- 两家新增机构的所有图片默认隐藏，收藏只保存指向原始档案的文字索引。原作品与媒体的使用权依官方记录和适用政策确定。

## 运行验收

1. 解压仓库运行 `python -m pip install -r requirements.txt`，再运行 `PYTHONPATH=. python -m pytest -q tests`。
2. 打开「世界名馆」，滚动至「跨机构真实馆藏探索路线」，选一路线和某一站，点击查询。
3. 在无网络下应出现明确错误与可点击官方链接；有网络时应显示真实结果，来源域名只能是指定的馆方域名。
4. 登录后收藏一件 NASA / LoC 记录，再进入「我的博物馆」「万物时光→我的收藏」，核对其默认私密、保留来源与日期。
5. 换账号重复同一记录收藏，两个账号应获得各自私人副本；非登录访问和恶意 `record_id` 均应被拒绝。

**测试范围说明**：离线自动化测试使用官方 API 的模拟响应，不等于 NASA、LoC、Met、NHM 线上接口都已在此环境实连成功。正式上线前仍需实际网络、许可证和浏览器全流程验收。
