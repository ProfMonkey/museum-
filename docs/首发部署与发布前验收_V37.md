# 万物博物馆 V37.0 — 首发部署与发布前验收

> 状态：**可作为部署准备说明，不等于已上线或已通过生产验收。**
> 仓库：`ProfMonkey/museum-`，后端 FastAPI + SQLite，前端在 `static/`。
> 本指南**不调用 GitHub Actions**。Railway 采用自己的构建/部署系统，不消耗 GitHub Actions 配额。

## 1. 推荐线路：Railway 小规模内测

1. 在 [Railway](https://railway.com/) 登录，创建项目并选 **Deploy from GitHub Repo**，连接 `ProfMonkey/museum-`。
2. Railway 会检测仓库根目录的 `Dockerfile` 构建整套 Python 后端和静态网站。不能选「纯静态网站」模式。
3. 给该 Web Service 添加 **Volume**，挂载路径设为 **`/data`**。此步骤不可省略：账号、展品、评论、进度记录和上传图片写入 SQLite / media 文件。
4. 在服务环境变量中设置：
   - `WONDER_DATA_DIR=/data`
   - `WONDER_COOKIE_SECURE=1`
   - 部署产生公开域名后，再设置 `WONDER_PUBLIC_ORIGIN=https://你的完整公网域名`（不要尾随斜杠）
   - `PORT` 由 Railway 提供，Dockerfile 会自动读取，默认值为 8000。
5. 在 Networking 里使用 **Generate Domain** 获取网站的 HTTPS 地址。HTTPS 域名设好后重新部署或重启，使 `WONDER_PUBLIC_ORIGIN` 生效。
6. 访问主页和 `/api/health`（应返回 `ok: true` 与当前版本号）。分别检查游客和普通账户的实际浏览器体验；公开 URL 正式发布前，不要放真实私人数据。
7. Railway 的服务运行/存储/流量费用和限制需在面板确认。建议从小规模、受邀内测开始，别将免费试用当作长期生产承诺。

## 2. 本地验收（**不用 GitHub Actions**）

在仓库根目录执行：

```bash
python -m pip install -r requirements.txt pytest httpx
python scripts/check_local.py
docker build -t wonder-atlas:v37 .
docker run --rm -p 8000:8000 -e WONDER_COOKIE_SECURE=0 -v wonder-data:/data wonder-atlas:v37
```

第二个终端打开 `http://127.0.0.1:8000` 和 `http://127.0.0.1:8000/api/health`。

至少亲自验收：

- 新账户注册、登录、退出，浏览器实际 cookie 行为；
- 创建/编辑/删除馆藏，公开与私密权限；多账户互相不能越权；
- 图片上传、重启后仍存在；真正持久化 SQLite；
- V24 转盘、V26 奇遇任务链、V32 谜案、V33–V37 公开/撤回联动；
- 手机与桌面入口、分享链接；没有公开数据时正确显示空状态；
- 测试失败时不对外宣布「全面通过」，未执行时不要宣称测试通过。

## 3. 对外开放用户投稿之前必须处理

当前是教学/实验性多人站点。**不建议未经以下加固便直接向不受限公网开放注册、上传和评论。**

- 运营：用户协议、隐私告知、版权/违规内容处理流程，明确举报和删除渠道；尤其是上传图片和原创故事；
- 安全：检查上传文件大小/类型与限额、IP/账户级注册和写入限速、管理员审核/封禁能力、日志与异常监控；现有进程内简单限速不能替代公网防滥用；
- 数据：持久卷和**独立的定期离站备份**（数据库使用 SQLite 安全备份方式，连同 `/data/media`），验证恢复流程；
- 资源：访客、注册、投稿规模逐步放开，监控磁盘占用、费用、响应时长；
- 合规：确认面向目标地区的域名、备案与用户内容合规要求。大陆境内服务器提供网站服务通常需要办理 ICP 备案；海外服务器并不代表可以忽略面向大陆用户的其他合规要求。

如果暂时没有运营审核能力，首发建议只开放**只读游客试玩 + 少量可信测试账号投稿**。

## 4. 面向中文用户的宣传顺序

- **小红书/抖音**：15–45 秒「把一碗米线变成自己的平行文明」「万物转盘决定今天吃什么」实际玩法录屏；
- **B 站**：3–5 分钟带完整游玩流程的视频（不要仅演示后台 API）；
- **V2EX 分享创造**：提供真实可用链接、Github 仓库、技术栈、特色玩法、已知限制，收集真实反馈；
- **GitHub README**：增加在线试玩、录屏、部署说明、问题反馈入口。

建议标题：**《我做了一个万物博物馆：任何东西都能收藏，甚至创造文明和跨世界故事》**。

**首发目标**：让新游客在 30 秒内无注册体验一个完整玩法；用户能记住「万物收藏 → 世界创造 → 世界碰撞」的独特机制。

## 5. 首发范围与状态

- 当前代码仓库公开，不代表网站已上线。
- 这是部署准备，不会自动帮你创建 Railway 账户、付费项目、持久卷或域名。
- 仓库的 GitHub Actions workflow 保持仅手动触发，本指南不使用它。
- 对外宣称「正式公测」前，需要补齐第 3 节的安全、审核和备份要求；做不到就标注**小范围测试版**。
