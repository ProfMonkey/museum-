# 万物博物馆 V29.0｜万物平行宇宙

**两个馆长的世界相遇，不意味着他们的私人世界自动合并。**

## 核心体验

V27 提供本人私密星图，V28 提供沿本人自建连线的私人航线。V29 只取双方**自愿指定且当前公开可访问**的真实展品，建立必须双方同意的跨馆会合，既让社区产生有趣的互动，又不打破原有的权限边界。

流程：

1. 馆长 A 从自己当前确实公开的作品中选一件，输入 B 的真实用户名，发送私人会合邀请。
2. B 在「万物平行宇宙」自己的收件箱内查看邀请。B 可以谢绝，也可以主动选择**自己的一件公开藏品**作为回应。
3. 只有 B 明确接受并选择作品后，才有跨馆会合桥梁。它不会公开 V27 私人星图、V28 私人航线或双方的私密藏品。
4. 双方可以独立点击「我已探索」；双方都标记后显示「双方自行完成」，并明确不是实际到访或真实科学事实证明。
5. 任一方可以结束已建立的会合，并清除双方的跨馆进度，不影响原始藏品或私人星图。

## 🔭 可解释交汇线索

用户选择自己当前公开的藏品，系统会检查最多最近 300 件**其他馆长确实公开、且其所属作品/世界也允许公开**的藏品，根据标签交集、相同类别、同领域推荐最多 8 条可解释线索：

- 「共同标签：云南」
- 「同属饮食文化类别」
- 「同属食物与饮食领域」

这是确定性元数据比较，不是假装具有 AI 理解，不自动宣称真实历史因果，也不等于其他馆长同意跨馆。即使没有找到线索，用户也能按准确用户名自行邀请拥有公开藏品的馆长。

## 数据表与权限边界

`parallel_invitations`：发起方和接收方账号 ID、源公开展品 ID、接收者选择的公开展品 ID、`pending/accepted/declined/cancelled/closed` 状态与时间戳。**不保存第三方藏品标题、标签、文本快照或私人图谱节点。**

`parallel_marks`：每个已建立会合中，各参与账号自行确认探索的时间。唯一键为 (invitation_id, user_id)。删除/结束会合清空标记。

- **双向主动授权**：发起和接受分别验证作品所有权与实时公开权限；只有被邀请的一方才能接受/谢绝。
- **严格隔离**：所有邀请查询、会合详情、打卡与终止，都必须登录且属于两位当事馆长；第三方与游客不可访问。
- **来源撤回**：任一源作品删除、变私密、所属玄幻世界/工作室/沙盒不再公开时，API 返回不含双方作品名称、标签及共同线索的不可用状态。解除撤回后重新核验。已经不可用的会合不允许新增探索标记。
- **防滥用上限**：单馆长最多 10 条待回应外发邀请、接收方最多 30 条待回应邀请、每位馆长最多 20 场已接受的会合。对同一个接收方至多存在一条未处理邀请，数据库唯一索引配合事务防止并发重复。
- **非自动公开**：跨馆会合只在参与者账号里可见，不会产生公共社区帖子、假馆长或公开个人关系网络。

## 接口

| API | 说明 |
|---|---|
| `GET /api/parallel` | 自己的公开作品、收件箱、已发邀请、有效会合 |
| `GET /api/parallel/suggestions?exhibit_id=N` | 从本人公开藏品寻找其他馆长的公开元数据重合线索 |
| `POST /api/parallel/invitations` | 使用本人公开藏品向真实馆长发出邀请 |
| `POST /api/parallel/invitations/{id}/accept` | 被邀请人主动选择本人公开藏品并同意 |
| `POST /api/parallel/invitations/{id}/decline` | 被邀请人谢绝 |
| `POST /api/parallel/invitations/{id}/cancel` | 发起人撤回待回应邀请 |
| `GET /api/parallel/bridges/{id}` | 双方可读的当前会合 |
| `PUT /api/parallel/bridges/{id}/mark` | 本人标记探索 |
| `DELETE /api/parallel/bridges/{id}/mark` | 本人取消标记 |
| `DELETE /api/parallel/bridges/{id}` | 任一方结束会合，清空双方进度 |

## 实现与验证

`parallel_universes.py`、`static/parallel.js`、`static/parallel.css`、`tests/test_parallel_v29.py`。

入口：「🌌 万物平行宇宙」独立导航，移动端同步提供入口。

当前为自托管 FastAPI + SQLite 的透明原型：不提供实时推送或大型分布式图搜索。跨馆真实用户推荐的准确性取决于真实公开藏品数量；没有匹配结果时正确显示空状态。真实浏览器视觉回归、大规模性能和反刷邀请机制仍需单独上线前评估。
