# 万物博物馆 V42.0｜统一搜索：不必先选分类，也能找到万物

状态：**独立开发分支**；无公网部署；不使用 GitHub Actions；本轮尚未运行完整 Python/浏览器集成测试。

## 为什么优先做搜索

V40–V41 已经建立了功能导航、分类维度和「藏品即入口」。但是用户搜索「猴子」时，不应先猜它是动物、游戏角色、网络热梗还是原创作品。**搜索先跨分类召回，再允许按领域等维度缩小结果**，这样分类是帮助，而不是门槛。

## 新入口

- 顶部、侧边导航和手机底栏：**搜索万物**。
- 功能地图仍叫 **找功能**，与找真实藏品明确区分。
- 在发现广场直接输入关键词，会进入新的统一搜索页；原有空关键词浏览和分类导航仍可正常使用。
- 键盘 `/` 聚焦统一搜索（在输入框等编辑区域内不会抢占按键）。
- `?search=关键词` 可以直达对应搜索页面，但不会把私密来源暴露出去。

## API

`GET /api/search?q=猴子&domain=...&category=...&series=...&time_bucket=...&sort=relevance&page=1`

响应：`items, total, page, per_page, has_more, facets, query, scope`。

- 范围：**本机服务器当前合法公开的社区藏品**。不宣称跨平台或包括「世界名馆」第三方开放馆藏；它们继续保留原有独立入口。
- 检索字段：标题、标签、细类、领域、简介、正文、馆长用户名；不要求先选分类。
- 空格分隔的多个词采用 AND（所有词均须在上述字段某处出现）；单个中文词按字面子串匹配。此阶段不做语义联想、拼音搜索或错别字自动纠正。
- `%` 和 `_` 是普通字符，不被 SQL 当作任意匹配通配符；查询均使用绑定参数，不拼接用户字符串。
- `relevance` 优先完整标题、标题前缀、标题包含、标签、类别、领域、简介、正文，再按真实点赞数及发布时间排序；`latest` 和 `popular` 可切换。排序属于导航策略，并不是对内容事实准确性的打分。
- `matched_in` 明确告诉用户结果在「标题、标签、类别、领域、简介、正文、馆长」中哪里匹配。
- 每页 16 件，返回是否还有下一页，不捏造任何展品。
- 筛选维度的计数来自 **关键词对应的当前公开语料，在应用用户所选筛选条件之前**，避免误以为是本页数量。
- 所有搜索结果和所有筛选计数都复用 `PUBLIC_SCOPE`：原物公开不够；原物所依赖的私密世界、创作工坊或沙盒撤回后，也不得进入结果、数量统计或筛选提示。本人私密作品不进入公共统一搜索；仍可通过「我的博物馆」查看。

## 移动端与零结果

窄屏自动将筛选项排成两列，查询输入与搜索按钮上下排列。筛选项可一键清除；无结果显示减小关键词、重置筛选、回发现广场的操作。搜索结果卡片仍用原有「藏品档案」交互，支持沿馆长关联、相似藏品和年代继续探索。

## 验证方法

在本机项目根目录执行：

```powershell
python scripts/check_local.py --quick
python scripts/check_local.py --js-only
```

集中测试：`tests/test_search_v42.py`。含跨动物/游戏/热梗/原创召回、多词 AND、特殊字符匹配、排序和过滤、私密来源撤回不泄漏及 16 件分页。

手动浏览器验收：
1. 进入顶部「搜索万物」，输入「猴子」，确认不同领域同屏显示；点击结果进入真实藏品档案，再返回。
2. 分别选领域、类别、年代、系列，确认数量变化；清除任一条件后能继续搜索。
3. 输入从未上传过的词，不应编造结果；输入 `%` 与 `_` 不应匹配一切。
4. 将一件已被搜索出来的公开作品改为私密，或撤回其依附的创作工坊；刷新搜索、筛选项、源档案，游客均不可见。
5. 用手机宽度确认筛选、搜索框、分页与结果卡片不溢出；分别检查功能地图与搜索万物不混淆。

## 下一轮的明确边界

目前仍使用 SQLite `instr()` 做字面检索；适合初期中小规模数据，不适合百万规模的全文或复杂语义检索。后续应先有真实数据量和性能基线，再考虑 FTS5 索引、中文分词、同义词词典和更精细的相关度排序；不要为了堆功能引入不透明的「AI 推荐」或编造搜索结果。
