# 万物博物馆 V32.0｜万物谜案馆

**万物皆可成为线索：真实馆长把真实公开藏品编成可玩的跨领域谜案，游客通过选择原始藏品破解。**

本版专注完整可用的“万物藏宝图”体验，不依赖外部模型、虚构的社区内容、实时爬取、后台定时任务或 GitHub Actions。

## 🎲 玩家视角：一段可推理的万物之旅

在主页选择「🗝 万物谜案馆」，可以浏览真实馆长公开的谜案，每条谜案有 **2—6 关**，每关由原作者亲自编写线索、提示和 3—4 个**当前真实公开**的展品选项。玩家需要登录以保存本人进度，也可以通过随机传送门进入一条当前确实有效的真实谜案。每条谜案的不同玩家进度相互隔离。

进入谜案后：
- 玩家最初只看到馆长写下的线索，以及可访问的真实公开藏品候选；答案标记不返回前端。
- 选择错误会记录一次尝试，并解锁馆长预先撰写的额外提示，之后可以继续回答。
- 选择正确才能进入下一关。服务器实时验证谜案仍公开且所有来源仍然可见。
- 全部通关后显示解锁路线，每站附真实藏品来源。1—3 星只根据本人的答错次数计算；这是**游戏计分**，不代表科学能力或馆藏事实核验。
- 玩家可随时主动重新开始，重置本人在这一条谜案的个人进度。其他玩家不受影响。
- 个人完成数量只是完成该谜题的**真实登录账号记录**，不会产生伪造的馆长、虚构数字或真假难辨的排行榜。

## ✍️ 馆长视角：从真实馆藏中创造故事

登录馆长能在谜案工坊：
1. 创建**默认私密**的谜案草稿（名称与开场叙事）。
2. 搜索真实公开馆藏标题、类别或标签，最多显示当前匹配的 24 件真实原始来源。
3. 在本次候选篮中挑选 3—4 件不同的真实公开藏品，指定唯一正确选项。
4. 撰写至少 12 字的线索与至少 6 字的错误后提示，保存为一关。
5. 集齐 2—6 关，每关答案来源不得重复。作者手动点击发布时，服务器再核验全部原始公开来源。
6. 发布后可暂停公开、撤下自己的关卡、修改原草稿，并重新发布。

每位馆长最多持有 15 条谜案路线。每条谜案只有经所有来源验证通过后才加入公共列表。线索来源于真实馆长的原创设计，不会自动声称知识已经核验。

## 🔐 原始来源权限与玩家隐私

- **来源不快照**：只存储展品外键 ID、题目文本、可访问公开选项及答案关系。标题、所属馆长、图片、领域等每次从原始公开数据库重新获取，不缓存他人作品快照。
- **撤回即下架**：如果任意原始选项删除、设为私密，或者被所属玄幻世界、创作工坊、沙盒的隐私设置遮挡，该谜案的公共介绍、随机推荐和玩家当前关卡立即不可用；不会展示已撤回作品的旧标题。
- **个人进度隔离**：`mystery_progress` 以 (谜案 ID, 用户 ID) 为主键，外部游客和其他玩家无法读取个人当前关卡、错误次数、线索提示或通关路线。
- **答题服务端裁判**：正确选项关系永不放进未通关的公共接口；不接受当前关卡没有列出的随意展品 ID，提交时再核验来源与当前进度。
- **版本保护**：编辑、撤下关卡、手动取消发布会增加谜案修订号、恢复私密草稿。旧版本的玩家进度不会直接迁移到新版本，避免旧进度被错误地视为新题答案。
- **公开收藏≠原作者认可**：选择他人当下公开的真实藏品作为“谜题候选”，不意味着对方认可本谜案的线索或结论；线索与答案由谜案作者独立负责。
- **作者权限**：只有原谜案作者能查看答案及编辑、发布、删除关卡。普通玩家只能看到候选选项和自己当前的私人游戏进度。

## 📚 数据表

- `mystery_trails`：馆长所有权、主题、开场叙事、私密/公开状态、修订号及时间戳。
- `mystery_stages`：谜案外键、原创线索、提示及正确原展品外键（来源删除后变 NULL）。
- `mystery_choices`：每关 3—4 个真实来源 ID、正确性标志（仅作者端接口可见），来源删除时级联移除候选。
- `mystery_progress`：每位登录玩家的私有修订号、已完成关数、答错次数、阶段错误数、完成时间。数据库按用户独立存储。

## 🌐 API

| 接口 | 说明 |
|---|---|
| `GET /api/mysteries` | 公开且所有选项仍有效的真实谜案 |
| `GET /api/mysteries/random` | 从真实已发布谜案中随机挑选 |
| `GET /api/mysteries/sources?q=` | 搜索当前合法公开的原始展品 |
| `GET /api/mysteries/mine` | 作者的私密/公开草稿、关卡与正确选项 |
| `POST /api/mysteries` | 创建私人草稿 |
| `PUT /api/mysteries/{id}` | 作者修改主题并进入新草稿版本 |
| `POST /api/mysteries/{id}/stages` | 作者添加线索关卡与 3—4 个真实藏品选项 |
| `DELETE /api/mysteries/{id}/stages/{stage_id}` | 作者撤下关卡 |
| `POST /api/mysteries/{id}/publish` | 严格核验来源和关数后公开 |
| `POST /api/mysteries/{id}/unpublish` | 私密下架并重置版本 |
| `DELETE /api/mysteries/{id}` | 作者删除谜案及其关联的私人游戏进度 |
| `GET /api/mysteries/{id}` | 仅提供公开简介与关数，不返回答案 |
| `GET /api/mysteries/{id}/play` | 登录玩家取得本人当前一关及公开候选 |
| `POST /api/mysteries/{id}/guess` | 服务端判题、错误提示、解锁下一站 |
| `POST /api/mysteries/{id}/restart` | 本人重置当前谜案进度 |
