# 万物博物馆 V37.0｜万物文明考古局

> 同一件**真实、当前公开的原始藏品**，在不同真实用户创建的**架空文明**中，可以拥有截然不同的角色：神圣遗物、日常工具、警示石碑、交易信物、历史记忆、未解之物。游客可以逐层发掘，最后在「同源解释图谱」中比较多个文明的想象。

这是一套诚实标注为**虚构创作**的互动考古叙事游戏：不是任何真实考古发现、大学博物馆鉴定、遗址登记、来源科学验证或原藏品作者的认可。

## 可玩功能

### ① 真实原物跨入架空历史
用户首先在 V33「万物碰撞机」构建自己的世界，再于 V34「文明演化实验室」完成至少两轮原创历史并主动公开。之后进入 V37「⛏ 万物文明考古局」，从目前真正公开的所有博物馆原始藏品中选择一件，把它与自己创建的有效公开文明关联，选择真实存在的架空历史轮次。

一座文明最多拥有 **12 项原创考古解释**；同一文明对同一原始藏品只能创建一项，避免用同一源无上限刷数据。可以编辑文字与角色，但**不能偷换原始文明和原物**。全部新作品默认为私密草稿，只有本人点击「公开」才加入展厅。

### ② 三层真实作者撰写的虚构考古谜题

每个考古档案有固定的三层材料：

1. **🔍 表层痕迹**：虚构遗址的第一眼观察，15–520 字。
2. **📜 深层碑文**：虚构文明居民如何解释此物，20–720 字。
3. **🪐 馆长最终假说**：亲笔写下当代原物为何在这个架空文明里成为某种象征，30–1100 字。

另有展题、遗址引子、年代定位、藏品真实来源链接与原作者署名。游客点击依次展开每层。真实登录用户的个人发掘进度在数据库独立记录；匿名游客也可以探索公开资料，但不会被伪装为实名参与者。

**坦诚设计说明**：分层是产品探索交互，不是安全加密。公开作品的每层内容可通过公开 API 直接读取；不要在公开考古层中放真正需要保密的信息。

### ③ 🌌 同源文明误读图谱

一件目前确实公开的原始藏品，在两个不同馆长的虚构文明里，可以拥有不同解释：

- 原物：某用户收藏的「微型计算芯片」。
- 文明 A 的创作者：把它写成一件「神圣遗物」。
- 文明 B 的创作者：把它写成一种「文明工具」。
- 观众可以查看同一原始藏品的**全部当前有效公开考古解释**及不同作者身份、角色和文明背景，最多 30 项。

页面里的「角色类型数」是本站这些真实馆长创作的游戏身份多样性，**不是事实分歧、历史证据强度或学术争议指数**。不捏造其他用户、实时出土新闻、考古机构结论或者虚假浏览量。

### ④ 上游真实来源与版本连锁保护

V37 **直接复用 V35** 已实现的 V34 来源验证与内容摘要逻辑。该验证器会实际校验：
- V34 文明为公开，确实属于创建者。
- V33 母世界仍公开、版本一致；其两件原始藏品在 V29 统一公开权限下仍合法。
- V34 历史中所有第三方注入的真实展品仍合法公开。
- V34 历史内容、源展品关键元数据及数据库编辑历代版本的摘要没有变更。
- V37 本身引用的这件真实藏品仍公开，且从创作时到现在的 `embassy_exhibit_epochs` 源版本没有发生变更。
- V37 指向的历史纪元确实存在于 V34 作者已经编写的历史年轮中。

只要任一来源撤回、上游世界/文明改变，当前公开考古资料即刻 404；公共列表与同源解释图谱都会过滤。即使创作者本人查看档案，也会收到不包含旧源标题、故事引子、三层文字的**来源失效占位**，避免透过引用项目继续泄漏已撤回的真实资料。

重新公开源作品**不会自动恢复旧考古档案**。作者必须主动点击「重新核验」（`rebase`），更新真实来源摘要并撤销旧版本，之后亲自再次点击发布。修改叙事文字、角色、时代、撤回公众访问也自动回到私密草稿，并将旧访客层进度失效。

### ⑤ 真实原藏品与私人叙事并存

V37 的原作者并非必须拥有被解释的原始藏品，但必须拥有**提供文化解读的虚构文明**。公开页面会持续注明：
- 原始藏品和真实馆长是谁。
- 虚构文明归谁所有。
- 哪位真实馆长撰写了虚构考古解释。
- **这是独立创作的虚构解读，不代表原藏品所有者认可或授予其它权利。**

原始藏品不被复制/转移产权，不更改 `exhibits.user_id`。若作者不希望作品继续公开，可以撤回考古解释或封存档案；源作品原封不动。

## API 与文件

| API | 说明 |
|---|---|
| `GET /api/archaeology/roles` | 六种架空角色、每文明12档/每档3层的上限 |
| `GET /api/archaeology/sources?q=` | 检索仍合法公开的真实原始馆藏 |
| `GET /api/archaeology/civilizations` | 当前用户自有的合法公开 V34 文明及真实历史轮数 |
| `GET /api/archaeology/public` | 最多40个真正公开且所有上游来源仍有效的虚构档案 |
| `GET /api/archaeology/mine` | 我的考古作品；来源失效时只有保密占位 |
| `GET /api/archaeology/exhibit/{id}/echoes` | 同一真实物件在不同虚构文明里的多种当前有效解释 |
| `POST /api/archaeology` | 创建默认私密的原创考古档案 |
| `GET /api/archaeology/{id}` | 公开考古导览/自己的私密草稿 |
| `PUT /api/archaeology/{id}` | 作者编辑三层文字或分类；新版本自动变私密 |
| `POST /api/archaeology/{id}/rebase` | 重验真实文明与原物版本；旧发布与进度清零 |
| `POST /api/archaeology/{id}/publish` | 作者复核当前有效来源并主动公开 |
| `POST /api/archaeology/{id}/retract` | 作者撤回公开 |
| `POST /api/archaeology/{id}/close` | 作者封存叙事档案，不删除原始展品 |
| `GET /api/archaeology/{id}/layer/{1,2,3}` | 游客展开真实馆长原创分层内容；实名访客按次序记录私人发掘进度 |

数据：`archaeology_relics` 存不可伪造的作者 ID / V34 文明 ID / 原始藏品 ID / 时代 / 文本 / 状态 / 版本摘要，`archaeology_progress` 存玩家各自私人层数，联合主键保证同人同档单条记录。

- `archaeology.py`：独立的 FastAPI + SQLite。
- `embassies.py`：只额外暴露现有 `civ` 权限/来源摘要验证器以供 V37 复用。
- `static/archaeology.js` / `static/archaeology.css`：黑金考古工作台、三层发掘、同源图谱、手机入口。
- `tests/test_archaeology_v37.py`：11 组 HTTP 集成测试（需要在本机执行）。
- `server.py` / `static/index.html` / `static/app.js`：V37 导航与 `?archaeology=<ID>` 当前公开档案分享。

## GitHub Actions / 测试边界

用户要求节约 GitHub Actions 额度，工作流已只有 `workflow_dispatch` 手动触发。本版本**不使用 GitHub Actions**，不调用它进行测试或部署。

可在本地执行：

```bash
python -m pytest -q tests/test_archaeology_v37.py
python scripts/check_local.py --quick
python scripts/check_local.py
```

本次仅使用静态 JS 语法解析检查前端构件；若没有实际执行本地集成测试、浏览器端到端流程与性能验收，就不声称它们已经通过。
