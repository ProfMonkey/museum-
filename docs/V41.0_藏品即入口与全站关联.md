# 万物博物馆 V41.0｜藏品即入口：有依据、能返回的关联探索

**状态：仅开发预览，没有公网部署；不使用 GitHub Actions。**

## 为什么改

V40 解决「从导航栏怎么找到一个功能」，但还没有完全解决「从一个真实藏品能否自然探索另一个真实藏品、为什么相关、走过去还能否回来」。

V41 把**真实藏品**作为组织中心：每件藏品的档案自身就是进入分类、时间、关联、收藏和互动功能的入口。

## 用户看到的体验

1. 用户打开一件真实公开藏品，首先看到原始档案、作者与原始来源；
2. 点击其领域、细类或年代，进入对应的真实筛选结果；
3. 继续向下看到「以这件藏品为中心」：
   - **馆长主动关联**：来自真实馆长提交的说明，带作者署名并明确标注未经事实核实。
   - **有依据的相似藏品**：只采用当前公开藏品的共同标签、同细类、同领域，逐条解释理由。
   - **相同年代的另一种发现**：只有宽泛年代桶相同，不捏造真实时间因果或事件关联。
4. 点击相关藏品，在当前档案中打开下一件藏品，同时记录「上一件」；想回去可在档案顶部直接点击返回。
5. 不想继续看这个主题，可以进入万物时光、已有分类关联图、随机奇遇、个人星图；原有收藏和万物转盘功能仍可用。
6. 当前合法公开的藏品可以复制直接可打开的原始档案链接（现有 `?source=<id>`）。

## 关联原则

数据真实、权限真实、理由可解释；**不得把虚构的关联说成历史事实**。

### API

`GET /api/exhibits/{id}/hub`

返回：
- `focus`：当前真实藏品基础分类与作者；
- `groups.curator`：最多 4 条作者手动关联；
- `groups.metadata`：最多 4 条从当前公开藏品真实元数据计算的匹配；
- `groups.time`：最多 4 条仅按同年代检索的真实藏品；
- `total` / `limits` / `method` / `notice`：结果数量、检索边界、排序方法、真实性提示。

性能与隐私约束：
- 推荐扫描上限 500 件当前真实公开藏品，按 ID 取最近样本；不能宣称涵盖所有历史发布作品。
- 先处理作者手动关联，再处理标签/类别/领域相似项，最后处理相同年代。
- 自动关联以共同标签个数、同细类、同领域确定性加权。这个权重只用于检索导航，**不是科学关联度或历史可信度**。
- 同一候选不跨分组重复出现。
- 只保留允许公开的来源：复用 `parallel_universes.PUBLIC_SCOPE`（原展品公开 + 母架空世界/创作工坊/沙盒上游公开）。若访问者本人是作者，则仍可以在自己的私藏内使用档案和手动连接。
- 同时修复原有 `connections_api.py` 关联图的上游私密来源可见性和手动关联写入边界。
- 任意来源变私密/所属私密容器撤回后，重新调用 hub API 时将其排除；不会从缓存接口返回已经失效的标题。
- 不新建伪造数据、不修改已发表关联、不迁移已有 SQLite 表、不引入云依赖。

### 前端与交互

- `static/object-hub.js` 提供嵌入档案的关联分组与返回路径；按移动端宽度自适应。
- `static/object-hub.css` 提供完整的分组、证据卡片、返回条与下一步导航的黑金样式。
- `static/app.js` 以 `/hub` 的数据替换旧的浅层「你可能还会喜欢」列表；在同一档案内保持单次探索的返回链（最多 35 站）。不依赖外部地图或网络图才能看懂。
- 将低频档案工具放进「更多操作」，保留已有成熟功能入口。
- 若用户要分享，直接复用 `?source=<id>` 而非自行发明另一种分享链接。

## 本机验证

源代码改动后先在项目目录执行：

```powershell
python scripts/check_local.py --quick
python scripts/check_local.py --js-only
```

手动验收场景：
1. 打开有同标签的两件公开藏品，点击「有依据的相似藏品」，理由显示具体共同标签；打开第二件，再返回第一件。
2. 打开有馆长主动关联的两个藏品，检查作者与「未经核实」提示。
3. 选择同年代但其他内容完全不相关的两个藏品；只能看到同年代对照，不应出现「历史因果关系」断言。
4. 把目标原始藏品设为私密，或把它所在的创作工坊设为私密；游客不应再能看到它，也不能通过旧版关联网络、hub API 或新建关联读到原有标题。
5. 从一件藏品进入时光、万物星图、关联图，再尝试返回首页；确认入口、返回和用途清楚。
6. 手机宽度下确认「馆长关联」「相似藏品」「相同年代」分组与折叠操作正常，档案不被几十个无意义按钮淹没。
