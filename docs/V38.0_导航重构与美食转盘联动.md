# V38.0｜导航信息架构重构与美食转盘闭环

**状态：开发预览；未部署、未对外发布。** 本次不调用 GitHub Actions，不进行公网部署。

## 设计依据

这次不是增加更多模块，而是处理「功能找不到、导航过长、主次不分」的问题。参考 Nielsen Norman Group 对导航和渐进呈现的研究：

- 同类入口应该放在一起，用户不必在一长串无差别链接中寻找。
- 首屏优先展示常用入口，把低频的高级功能放到清楚命名的次级分组中。
- 当功能很多时，需要按有意义的主题分组，并提供一个能直接定位功能的索引。
- 主页应当展示少量真实、有代表性的内容入口，而不是堆满每个模块的宣传按钮。

参考资料：
- https://www.nngroup.com/articles/113-design-guidelines-homepage-usability/
- https://www.nngroup.com/articles/progressive-disclosure/
- https://www.nngroup.com/articles/menu-design/

## 一、导航重组

### 桌面侧栏：核心功能始终可见

1. **核心功能**：发现广场、世界名馆、今天吃什么、心动收藏、我的博物馆。
2. **探索发现**：万物时光、万物雷达、当代新奇、随机奇遇、万物星图。
3. **创作与游玩**：发布新发现、展厅工坊、万物实验室、互动玩法、命运接力。
4. **专题世界与故事**：玄幻异界、平行宇宙、联合展厅、活体博物馆、谜案馆、万物碰撞机。默认折叠。
5. **文明与合作**：文明演化、文明大使馆、遗产交换站、文明考古局。默认折叠。
6. **个人与系统**：回忆剧场、功能热度、通知中心。默认折叠。

进入折叠组中的页面时，侧栏会自动展开包含当前页面的分组；当前页面继续保持明确的选中态。

### 手机底部导航：五个稳定入口

- 发现
- 找功能
- 转盘
- 发布
- 我的

不再把二十多个模块塞进横向滚动的底部导航。

### 可搜索「功能地图」

新增 `static/feature-map.js`。用户可通过侧栏、顶部按钮、首页入口或键盘 `/` 打开功能地图；按用途分组浏览，输入「美食」「上传」「文明」「谜题」「时间线」等词，实时筛选对应功能。功能卡片直接跳转到原有页面，不创建第二套功能实现。

这里搜索的是**功能入口**。查找具体藏品仍然使用发现广场原有搜索。

## 二、首页减负

首页首屏只保留四个常用行动：
- 分享我的发现
- 找功能
- 随机奇遇
- 今天吃什么

世界时光、互动玩法、命运接力等低频入口不再同时抢占首屏按钮，仍然可从导航和功能地图进入。

## 三、美食浏览与转盘真正连接

### 从真实美食藏品直接进入

当公开藏品的标题、简介、故事、领域、分类或标签命中常见食物词汇时，藏品详情中的转盘入口会明确显示为「🍜 加入『今天吃什么』转盘」。其他藏品保留通用「加入万物转盘」入口。

### 按场景进入正确的转盘

- 从美食藏品点击入口后，转盘会选择用户现有的美食转盘；如果登录用户尚未创建，就自动创建「今天吃什么？」私人转盘。
- 游客进入临时美食转盘，不需要登录。
- 游客把真实公开的美食藏品加入临时转盘时，会在本地保存藏品 ID。抽中后可以继续打开原始藏品，而不只是得到一个失去来源的标题。
- 登录用户将真实藏品加入服务器端私人转盘，继续使用已有的权限检查与来源撤回保护。
- 点击「吃什么」场景时，登录用户会切换到已有对应主题转盘；不存在时才创建，不会悄悄把其他主题的转盘改名。

### 美食藏品快捷搜索

在「吃什么」转盘中新增「快速寻找馆内美食」快捷词：米线、菌子、牛排、烧烤、甜品、水果、茶饮、地方小吃。它们只查询真实、当前公开的博物馆藏品。若没有找到匹配结果，界面会说明当前没有结果，用户仍可以手动加入食物，不会伪造馆藏。

同时，`/api/wheels/sources` 的关键词匹配扩展到标题、简介、分类、领域和标签。

## 四、变更文件

- `static/index.html`：分组侧栏、五项移动导航、功能地图脚本、开发预览状态。
- `static/style.css`：折叠组、功能地图卡片与响应式布局。
- `static/app.js`：功能地图路由、当前分组自动展开、快捷键、首页减负、食品藏品详情入口。
- `static/feature-map.js`：可搜索的功能入口目录。
- `static/wheel.js`：按食物场景自动选/创建转盘、游客原始藏品来源保留、食物快捷搜索、场景切换。
- `static/wheel.css`：美食快捷入口样式。
- `wheel_api.py`：来源搜索增加分类、领域和标签匹配。
- `tests/test_wheel_v24.py`：增加分类/标签匹配测试。

## 五、验证状态

已对修改后的 `static/app.js`、`static/feature-map.js`、`static/wheel.js` 做 JavaScript 语法解析检查。新增了一个 Python 集成测试，但**没有运行 Python 测试、真实浏览器端到端测试或手机实测**，因此不能宣称功能完整验收通过。

建议本机验收顺序：

1. 打开功能地图，搜索「美食」「文明」「谜题」，确认结果和跳转。
2. 确认桌面侧栏只展开常用组，进入专题页面时能自动展开所在组。
3. 游客打开一件标题/标签命中食物词的公开藏品，点击「加入今天吃什么」。
4. 加入第二个选项，抽取一次；如果抽中的是原始馆藏，点「查看抽中的馆藏」确认返回原档案。
5. 登录后重复流程，确认新增的是私人美食转盘，且不会把私密藏品放进公共搜索结果。
6. 用手机宽度检查底部五项导航、功能地图搜索和转盘布局。
