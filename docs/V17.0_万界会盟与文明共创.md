# 万物博物馆 V17.0｜万界会盟与文明共创

## 目标

让两位真实的博物馆用户分别拥有一个虚构世界，并通过**双方同意**共同创作跨界史诗。不要伪造用户、互动量、官方故事、历史事实或资产交易。

## 三条主线

### 一、文明档案

馆长可以在自己创建的虚构世界里添加最多 6 个文明，填写文明名、首都、世界信条、族群风格、背景小传和可见范围。默认仅本人查看。只有世界开放后，才可公开文明档案；关闭世界会把其文明档案转回私人状态，重新开启世界不会自动恢复公开。

### 二、双向同意的万界会盟

馆长先将自己的一片世界公开，再邀请另一个账号已公开的世界。仪式类型：文明会盟、天道辩论、异界互市、法则碰撞。用户填写邀约后进入待回应状态，受邀馆长可接受或拒绝，提议者可撤回；不能替别人同意或主动操控他人世界。每对世界最多 1 个未完成／已接受的会盟。限每账号 12 个待回应、150 份总邀约，每对世界历史最多 6 次邀约。

接受后产生一个**确定性原创剧情框架**，由双方世界的名称、法则、仪式和会盟编号计算。双方规则只在虚构文本中相遇，不修改任何世界法则，不转移藏品、物品、账号资产或金钱。

### 三、共创纪事

两位馆长均可提交章节：2–75 字标题，20–1200 字正文。章节初始只有双方可见；另一方明确批准才允许所有人查看。原作者不能批准自己撰写的章节。拒绝的章节不公开。每会盟最多 40 章，每作者最多 8 份待审核章节。

## 权限与撤回规则

- 只有已公开且仍公开的两个世界，其已接受会盟才在公共馆区可见。
- 主动关闭任意世界，相关会盟状态统一撤回；文明档案恢复私密。以后重新公开世界，不得自动恢复已撤回的内容。
- 世界所有权、奇物所有权不因会盟而改变；任意涉及商业交换的字眼仅为虚构世界中的文学描述。
- 删除世界后，关联的文明、会盟及共创章节由外键级联删除。数据必须由双方主动创建，不使用虚构演示用户充当真实人。
- 公开内容仍需要站点未来完善的评论举报、反垃圾机制与内容审核；当前接口含基础上限，不代表已具备生产级内容安全系统。

## API

`GET /api/fantasy/council/config` — 世界会盟设定；
`GET /api/fantasy/council/worlds` — 公共世界与自己的世界；
`GET /api/fantasy/council/civilizations/{id}`、`POST /api/fantasy/council/civilizations`、`PATCH /api/fantasy/council/civilizations/{id}/visibility`、`DELETE /api/fantasy/council/civilizations/{id}` — 文明档案；
`GET /api/fantasy/council/encounters?scope=public|mine`、`POST /api/fantasy/council/encounters`、`GET /api/fantasy/council/encounters/{id}`、`PATCH /api/fantasy/council/encounters/{id}` — 邀约状态；
`POST /api/fantasy/council/encounters/{id}/chapters`、`PATCH /api/fantasy/council/chapters/{id}` — 双向审核章节。

## 前端与验证

本版本延续原「玄幻异界」页面，增加四号页签「☯ 万界会盟」，内部文明典藏、发起会盟、公开共创年历三屏，CSS 为移动端响应式布局，不增加首页重复的顶级模块。交互不会依赖外部 AI。

开发环境中可执行：

```bash
python -m pytest -q tests/test_diplomacy_v17.py
node --check static/diplomacy.js
node --check static/fantasy.js
```

测试的独立 HTTP fixture 使用模拟的账户身份提供器，只验证实际 SQLite 和路由的权限判断；完整整站 cookie 登录、端到端手机浏览器、部署环境安全仍需要进一步验收。
