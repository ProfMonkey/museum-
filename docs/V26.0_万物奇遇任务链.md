# 万物博物馆 V26.0｜🗺️ 万物奇遇任务链

**从随机抽中一件东西，到真正打开另一座展厅。**

V24 的「万物转盘」让馆长决定下一件想法；V25 的「万物命运接力」让不同选择连成一次私人奇遇；V26 让每个已经抽出的结果成为一次**真实博物馆探索入口**，并能自行记录参观进度。

## 1. 主要体验

进入左侧「✨ 万物命运接力」，先按原有规则创建/抽取一张奇遇卡。在卡片下方新增「🌌 从抽到的万物，走进另一座展厅」：

- 每一站尚未抽取：显示 🔒 尚未解锁，不提前给出假的目的地。
- 抽到手动文字（例如「米线」）：只检索当前**真正公开**的馆藏标题、简介和标签；列出明确写明匹配原因的藏品卡，可打开原始收藏档案。
- 抽到来自博物馆的一件真实公开展品：优先展示**命运源藏品**，随后列出文本匹配的其他来源。
- 没有文本匹配但当前有公开藏品：显示「🧭 随意逛逛」，明示它不是相关性推荐；如果博物馆仍没有内容，给出真实空状态，不伪造推荐。
- 用户可以点击「我参观过这件」，将当前任务收藏为自己的私人进度，也可「取消标记」。这是用户本人**自行标记**，服务端不宣称验证了真实参观行为。
- 游客也可以点击某个已抽中的演示词，「从博物馆寻找线索」，直接调用公开检索，不生成虚构社区用户，也不创建私人进度。

用户在本版看到的是可以核验来源的实际馆藏，不是预先构造的满屏虚假内容。界面复用原有藏品详情入口，不改变旧有转盘、公开奖励、访客概率。

## 2. 透明的检索规则

本版**不是 AI 推荐系统**，也不宣称语义理解。

后端在**最近 400 件仍公开且合法可见的展品**中检索文本线索，并单独补取命运源展品和用户曾标记过、但不在最近 400 件中的老馆藏。匹配优先级为：

1. 标题完全一致；
2. 标题包含抽取词；
3. 标签包含抽取词；
4. 简介包含抽取词；
5. 中文双字词片段重合（只能作为弱线索）。

按规则返回最多 4 件文字匹配展品。未命中时最多返回 3 件明确标明**非相关推荐**的开放藏品。绝不会把未经独立认证的内容当作真实史实或专业建议；未来可根据真实用户内容逐步改进关联探索。

## 3. 私人任务进度与数据结构

新增 `wonder_adventure_visits`：每张奇遇、每一站最多一件用户自标记参观的真实公开藏品，保存其 ID 与时间；不存展品的私人标题快照。只由当前奇遇所有者读取、增加、取消。

访问所标记的展品发生以下变化时：

- 展品从 public 改成 private：当前任务立即不展示其标题，不计为有效参观；
- 展品被删除：SQLite 外键 `ON DELETE SET NULL`，原标题不再显示；
- 源藏品从 public 改成 private：该站不再按曾公开时的标题生成新的相关发现；
- 源馆藏来自私人幻想世界或撤回发布的创作工坊：同样不能用于 V26 的当前公开发现。

V26 的私人进度**不会自动出现在** V25 已公开的奇遇卡页面/API 中，不会因一次自标记参观就发布给其他人。

## 4. 后端与前端

- `discovery_missions.py`：公开文字检索、安全来源过滤、任务展示、私人自标记/撤销 API。
- `static/quests.js`：探索卡片、游客临时搜索、馆藏详情跳转、本人进度。
- `static/quests.css`：沿用万物博物馆深蓝金色系，加入来源标记、解锁状态、任务卡自适应。
- `static/adventure.js`：在 V25 路线内容下方接入 V26 任务。
- `server.py`、`static/index.html`：版本升级到 V26、注册 API 和新前端资源。
- `tests/test_discovery_missions_v26.py`：多用户边界、公开检索、动态撤回、任务开始限制、人工进度与原有功能回归。

API：

| 路由 | 说明 |
|---|---|
| `GET /api/discovery/quests/config` | 公开规则及术语 |
| `GET /api/discovery/quests/explore?q=...` | 游客/登录用户搜索真正的开放馆藏 |
| `GET /api/adventures/{id}/quests` | 仅所有者可查看的阶段关联及私人参观进度 |
| `POST /api/adventures/{id}/quests/{n}/visit` | 自行标记当前阶段允许的一件公开馆藏 |
| `DELETE /api/adventures/{id}/quests/{n}/visit` | 取消自行标记 |

## 5. 验收和限制

本版重点在**真实数据、可解释词汇、实时权限、私人状态**四点。历史资料本身真实性由投稿者负责；字符串匹配无法保证真实语义相关。

如有用户创建数百万个藏品的需要，下一步应从最近 400 件的受限简单索引检索升级到 FTS5 或专用倒排索引，避免无界扫描。

GitHub Actions 检查 Python 自动化集成测试及第一方 JS 语法。真实手机/桌面浏览器视觉端到端、实际社交传播、真实语义评价和百万数据下的性能仍需单独验收。
