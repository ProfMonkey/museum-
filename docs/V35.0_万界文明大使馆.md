# 万物博物馆 V35.0｜万界文明大使馆

**让 V34 的两座真实用户原创文明互相派遣使者、共同撰写架空外交史。没有真实双方同意就绝不公开。**

## 🌌 创新机制

与单人创建世界不同，V35 需要真实的两位馆长：

1. 馆长 A 在自己**已经公开**且全部源作品有效的 V34 文明中选择一座，再选择另一位真实用户的合法公开 V34 文明。
2. A 写下**私密**外交邀请与舞台前言，发送给 B。B 可以接受或拒绝，A 可以在 B 同意前取消。
3. B 同意后，两位馆长分别以**自己的账户**撰写至少一封原创外交书信。所有信件都明确署名，作者只能撤回自己写的信。
4. 两位馆长必须分别批准**同一个内容修订版本**。双方批准齐全后，才会出现「万界文明外交纪事」的游客公开页面。
5. 任何一人新增/撤回书信，或修改联合标题与前言，都会同时撤销双方旧版批准，使外交纪事再次成为私人草稿。
6. 任一参与者可以撤回公开许可或结束合作，不会删除两位馆长自己的 V34 文明、V33 碰撞世界或真实原始藏品。

每位馆长最多同时参加 12 个待确认、进行中或已公开的使馆。每座使馆最多 12 封外交信。历史关闭或拒绝的邀请仍供相关参与者查看状态，但不会出现在公共目录。

## 📜 独特玩法

### 双向国书

A 可以写：

> 我们的青铜帝国第一次看到了来自机械国度的陌生芯片，愿意交换十卷历史知识。

B 必须用自己的账号亲笔回复：

> 机械国度希望从古代钟声中寻找更古老的时间算法，向贵国发出正式交流邀请。

这些只是示例；系统**不会**冒充 B 写下回复，也不会编造真实用户。

### 世界变更使旧外交失效

文明并不是永久不变的。V34 文明可能增加一次决策、修改名称、撤回公共权限，V33 母世界可能修订世界法则，原始藏品、玄幻世界、工作室、沙盒也可能撤回公开。

V35 为双方有效 V34 文明计算哈希签名。签名包含文明名称/宣言、V34 全部原创历史回合、V33 世界版本与名称、两件原始藏品和注入的第三件外来藏品的当前标题。签名用于**核验版本**，不把外部创作全文复制进使馆数据库。

任何一端：

- 来源撤回 → 公开详情与目录立即失效。
- 原文明重写并重新公开 → 哈希不匹配，原有外交文本继续私密，双方必须重新核验并重新审批。
- 原始馆藏标题改变 → 旧外交基于不同版本，不自动继续公开。

「重新核验」可由任一参与者主动执行，但会重置双方批准、增加纪事修订号；在双方再次确认前，游客看不到旧故事。

作者自己的使馆列表在源失效时**只显示封锁占位**，不会继续返回旧源文明名称、联合标题、前言或外交书信内容。关闭/取消/拒绝后的使馆不允许偷偷追加书信。

### 双向同意而不是系统生成的虚假外交

这里提供的是**架空创作场景**：两位用户分别创作自己文明的语言与态度，系统只负责关系、权限、公开签名、版本与展示。

这不是政治或国际关系预测，也不模拟现实中的政府或授权使节。

## 🧩 API 路由

| 方法及路径 | 用途 |
|---|---|
| GET `/api/embassies/public` | 只展示双人同意且全部来源当前有效的外交纪事 |
| GET `/api/embassies/mine` | 本人邀请及可选真实公开文明 |
| POST `/api/embassies` | 向另一位真实馆长发出私人邀请 |
| GET `/api/embassies/{id}` | 参与者预览 / 获准公开游客读取 |
| POST `/api/embassies/{id}/accept` | 被邀请者接受 |
| POST `/api/embassies/{id}/decline` | 被邀请者拒绝 |
| POST `/api/embassies/{id}/cancel` | 邀请人撤销仍在等待的邀请 |
| PUT `/api/embassies/{id}` | 参与者修改标题、前言并重置双方批准 |
| POST `/api/embassies/{id}/letters` | 某一真实馆长写一封自己的外交信 |
| DELETE `/api/embassies/{id}/letters/{letter_id}` | 仅原信件作者撤回 |
| POST `/api/embassies/{id}/approve` | 某位参与者批准当前修订版，两票才公开 |
| POST `/api/embassies/{id}/retract` | 任一参与者撤回双人公开批准 |
| POST `/api/embassies/{id}/refresh` | 双文明重新核验当前版本，清空旧批准 |
| POST `/api/embassies/{id}/close` | 任一参与者关闭使馆 |

## 🔒 数据库与隐私

- `civilization_embassies`：双方真实 user ID、双方真实 V34 文明外键、各自历史来源摘要、邀请与联合审批状态、修订号、更新时间。
- `embassy_letters`：使馆 ID、真实作者 ID、原作者自行撰写的主题与正文、服务器录入时间。
- 没有 AI 自动伪造回答、空账户、无主信件。用户资料没有被其他用户跨馆访问。
- 公共页面每次都重新检查 V34 的世界发布状态、所属真实馆长、母 V33 修订号、所有当前合法公开来源与完整历史摘要。
- 不向访客泄露未接受、未批准、已关闭、父来源失效的书信。
- 登录用户的私人使馆在失效时也不会泄露旧原始藏品的标题与旧外交内容。
- SQL 修改操作使用事务与约束防止重复邀请和跨账户书信。
