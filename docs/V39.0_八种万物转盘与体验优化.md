# 万物博物馆 V39.0｜万物决策中心：八种转盘＋用户体验优化

**状态：本机开发预览，尚未对外发布。** 原仓库 `ProfMonkey/museum-`。本次不调用、不启用 GitHub Actions。

## 本轮目标：不要再制造找不到入口的新功能

用户指出了两类问题：
1. V38 的美食场景形成了部分闭环，但其他转盘仍像彼此孤立的单页游戏。
2. 多次浏览会找不到曾经用过的功能；游客切换食物、影视、旅行会把候选项混在一起，还要多次确认才能把藏品加入转盘。

这次的重点是改善**从发现藏品到作出选择**的完整路径，并降低记忆负担。

## 一、八种真正分离的选择场景

| 场景 | 实际用途 | 灵感候选（只是本机演示，不是社区真实投稿） |
|---|---|---|
| 🍜 吃什么 | 晚饭、周末餐饮 | 米线、菌子火锅、牛排、烤鱼 |
| 🧭 去哪玩 | 户外、旅游、展览 | 逛博物馆、去湖边、公园漫步 |
| 🎬 看什么 | 电影、动漫、纪录片 | 科幻电影、纪录片、动画 |
| 📚 读什么 | 纸书、古籍、小说 | 科普读物、传记、小说 |
| 🧠 学什么 | 自学、课程规划 | 数学、编程、英语、算法 |
| 🏃 怎么运动 | 跑步、篮球、拉伸 | 慢跑、篮球、骑行 |
| 🎲 做什么 | 休闲、摄影、动手尝试 | 听音乐、动手做实验 |
| ✦ 自定义 | 用户随意定义自己的主题 | 研究一个问题、画画 |

免费游客：八个主题分别保存候选项、历史和转盘设置，只在自己浏览器中的 `wonder-wheel-v39` 里存储；旧的 V24 本地数据支持迁移。**切换到旅行不再拿食物进行抽取**。

登录馆长：每个主题优先复用本人原有的独立私人转盘；不存在时按原有账户限制创建（每人最多12转盘，每转盘24项）。不会自动改动别的主题的现有转盘。

## 二、藏品详情直接转盘化，不再只识别美食

在任意**当前公开**的原始藏品详情中：
- 系统依据公开展品**标题 / 领域 / 分类 / 标签**给出一个**可更改的建议场景**，如电影 → 看什么、旅游景点 → 去哪玩、小说 → 读什么、数学 → 学什么、篮球 → 怎么运动。只提供快捷分类提示，并不宣称内容是经过学术分类认证。
- 用户点击推荐入口，**一次点击**就进入对应的私人或游客转盘并加入原始藏品，不再必须去下一页重复点击「加入」。
- 用户还可以展开「↔ 放到其他类型的转盘」自由选择**八种目的地**。例如可以把一个电影海报放入「学习」转盘进行摄影构图分析；把一张历史古画放进「旅行」转盘当作出游灵感。
- 同样内容不重复添加；游客转盘里的演示项若与真实藏品同名，可将现有选项升级为带源 ID 的真正馆藏选项。

## 三、抽奖与源资料之间的闭环

- `GET /api/wheels/sources?q=`：在**真实当前公开**馆藏中按标题、简介、类别、领域、标签检索。
- `GET /api/wheels/resolve?ids=...`：只返回当前可公开的原始馆藏；用于游客对自己保存的来源引用重新核验。
- 通过 V29 `PUBLIC_SCOPE` 统一权限判断，避免源藏品所属的玄幻世界、展厅工作室或沙盒项目变私密后，转盘依然显示原来的公开标题。
- 若来源撤回或更名，游客临时转盘会同步或移除相应缓存选项、相关抽取记录；登录用户继续使用 V24 的实时来源过滤和私密历史。
- 游客因网络故障无法核验保存的原始馆藏时，转盘**暂停显示这部分缓存内容和抽取**，提供「重新连接检查」按钮，不让撤回的源标题被错误当作公开数据。
- 仍然由服务器 `secrets.randbelow` 做**等概率随机**（启用连续防重复时会公平地排除上一项），没有付费抽取、概率操控或虚假真人参与。
- 抽中的选项若是原始藏品，可继续打开原始馆藏记录。

## 四、显著改善交互

1. **三步引导**：选择场景 → 放入两件以上候选 → 点击抽取；界面不再塞入八套演示模板的重复按钮。
2. **每场景的真正馆藏快捷搜索**：旅行搜景点、建筑；影视搜电影、动画；阅读搜古籍、小说；学习搜数学、编程；运动搜篮球、跑步；活动搜摄影、实验。找不到就提示，不编造真实馆藏。
3. **当前状态清楚**：高亮八种场景的当前选择，增加 `aria-pressed`，更容易识别自己在哪个转盘。
4. **即时记录**：抽取动画完毕就刷新私人/本地历史，不必多点击一次才看到结果，且保留指针朝向抽中项。
5. **降低动态效果的障碍**：浏览器开启系统「减少动态效果」时，转盘减速动画和等待时间一并缩短。
6. **最近使用功能**：在「功能地图」顶部增加最近访问功能的入口（最多 6 个），仅存当前设备，不上传记录，搜索时隐藏这块辅助区域。
7. **移动端可用性**：八个主题以两列可点区域布局；不修改 V38 精简后的 5 个底栏主入口。

## 五、文件

- `static/wheel.js`：八场景独立状态、自动添加、合法来源核验、轻量动画与即时历史。
- `static/wheel.css`：八场景移动端适配。
- `static/app.js`：原始藏品详情转盘场景识别和手动改选；最近使用入口记录。
- `static/style.css`：原始藏品详情中放入转盘的交互分组。
- `static/feature-map.js`：八场景搜索描述与最多 6 个本地最近使用功能。
- `static/index.html`：主入口统一命名为「万物转盘」。
- `wheel_api.py`：八个服务端主题、安全公开展品即时解析、统一来源公开范围。
- `tests/test_v39_wheels.py`：多场景与公开源访问的 HTTP 测试。
- `tests/test_wheel_v24.py`：继续保护旧版随机和来源撤回回归路径。
- `scripts/check_local.py`：本机 `--quick` 增加 V39 测试，不调用远程 Runner。

## 六、为什么按这个方向优化？

Google / Android 的导航设计指导建议把手机底栏留给少量顶级目的地（一般 3–5 项），而将其他功能通过归组、次级导航等方式呈现。这支持我们在 V38 把 25 个底栏入口压缩到 5 个入口，在 V39 进一步放入用户「最近使用」路径：
https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns

所有体验设计必须通过**真实浏览器**检查；静态脚本语法检查不能证明事件、布局和联网访问都正确。

## 七、本机验收（不消耗 GitHub Actions）

```powershell
python scripts/check_local.py --quick
python scripts/check_local.py
```

首次浏览器手测：
- 游客从一件电影、一本书、一条运动馆藏打开相应转盘，确认不再需要点两次加入；抽中带来源的项目能返回原展品。
- 游客切换电影/美食/学习，确认三个场景各自保持候选与历史；旧本地 V24 数据可迁移。
- 登录用户切换场景，确认新建 / 复用私人转盘，不混合项目。
- 将源展品改为私密/撤回后，游客和登录馆长都不能从轮盘查询或旧抽中记录泄漏源名称。
- 手机宽度检查八场景按钮、功能地图最近使用与藏品详情展开菜单。
- 网络异常时，若来源不能核验，界面明确阻断旧源标签的展示和抽取。

**GitHub Actions 自动触发仍关闭。** 不部署网站，不承诺没有运行过的集成测试通过。
