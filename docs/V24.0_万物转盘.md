# 万物博物馆 V24.0｜🎡 万物皆可抽 · 今天吃什么？

**设计起点**：用户在博物馆里逛到一道美食、看见一本书、一部电影、一个有趣的地方，都可以收藏进自己的「万物转盘」。等遇到选择困难时，转动转盘，让系统等概率选出一项。

这是**娱乐与生活决策功能**，不是付费抽奖或博彩，不含任何奖品、投注、赌场设计或财务建议。

## 1. 支持的场景

- 🍜 今天吃什么：米线、火锅、牛排、菌子等；
- 🧭 去哪里玩：公园、博物馆、咖啡馆、露营；
- 🎬 今天看什么：电影、纪录片、动画；
- 🎲 现在做什么：休闲、运动、创作、学习；
- ✦ 自定义：任何文本或者逛博物馆时发现的真实公开展品。

演示模板作为**系统提供的示例灵感词**明确标注，并不伪造用户投稿、好友分享、店铺信息、热门榜单或真实社区内容。

## 2. 从万物博物馆加入选项

打开任何仍公开的真实社区展品详情，在操作区点击 **「🎡 加入我的万物转盘」**。系统记住这件公开展品，进入转盘页面时可选择目标转盘并点击添加。也可以直接使用转盘内的公开馆藏搜索。

每个用户最多创建 **12** 个私人转盘，每个转盘最多 **24** 个选项。手动文本或公开馆藏都可以加入同一个转盘。重复自定义名称与同一源藏品不能重复添加。

一件源藏品改为私人或删除后，会被实时排除出可抽范围。旧抽取记录改显示「已移除或撤回的选项」，不会通过用户历史展示被撤回的藏品名称（只有当前仍公开的藏品标题才可见）。暂不对用户开放分享私人转盘，以避免来源隐私扩散。

## 3. 服务端抽取规则

每次点击开始抽取，服务器用 `secrets.randbelow` 在**当前有效候选项**之间均匀抽取，返回命中选项序号。前端再根据服务器返回的中奖序号播放 SVG 转盘减速动画，而不是靠 CSS 动画随机产生结果。

- 默认允许打开「不连续抽到同一项」。开启后，如果有效选项超过 1 件，从候选集中排除上一次有效结果，因此余下项目**等概率**；并不意味着当前所有项目等概率，包括被排除的上次结果。
- 关闭防重复后，每次都是完整有效选项之间等概率，有可能两次连续选中同一项。
- 有效选项不足两项时，服务器返回 409，前端不发起抽取。
- 每个私人转盘保留最近 20 次结果，按用户隔离。
- 不提供「必中某选项」、暗箱权重或后台操纵的选项；颜色只是视觉主题。

## 4. 免登录体验

首次访问「🎡 万物转盘」的游客可看到一个明确写着「演示选项」的食物转盘，默认选项是米线、菌子火锅、牛排、烧烤。不是虚构的真实用户数据。

游客可以修改选项、切换话题、选择配色，并通过 `POST /api/wheels/preview` 让服务器抽取。编辑数据与最近记录仅存于**自己的浏览器 localStorage**，不存入服务器账号，清理浏览器数据后会消失。登录后使用专门的数据库转盘收藏系统，游客本地转盘不会被自动绑定账户。

## 5. 风格与交互

- 深色博物馆界面与高饱和的琥珀／星云／生命／玫瑰四色轮盘。
- 真正按选项个数动态生成的 SVG 扇形，指针固定、转盘旋转，服务器结果对应最终角度。
- 视觉减速旋转、状态说明、最近抽取历史。
- 手机和平板响应式排版，键盘可使用按钮，SVG 提供辅助标记。
- 用户按已公开展品跳转原有藏品详情，而非另做第二套内容体系。

## 6. 模块和接口

- `wheel_api.py`：表 `wonder_wheels`、`wonder_wheel_items`、`wonder_wheel_draws`，随机数、来源权限与有限历史。
- `static/wheel.js` 和 `static/wheel.css`：完整交互、SVG 转盘动画与游客本地状态。
- `static/app.js`：接入主页、路由和公开藏品详情快捷按钮。
- `static/index.html`：左侧导航独立「🎡 万物转盘」。
- `tests/test_wheel_v24.py`：身份隔离、来源撤回、访客选项、来源搜索、公平随机、防重复、容量和历史测试。

API：

- `GET /api/wheels/config`、`GET /api/wheels/sources?q=...`。
- `POST /api/wheels/preview`：游客模式临时抽取，不写账号数据库。
- `GET/POST /api/wheels`：我的转盘列表及新建。
- `GET/PATCH/DELETE /api/wheels/{id}`：私有转盘管理。
- `POST /api/wheels/{id}/items`：加手动选项或公开馆藏。
- `DELETE /api/wheels/{id}/items/{item_id}`：移除自己的选项。
- `POST /api/wheels/{id}/spin`：服务端抽取并保存私人记录。

## 7. 验收边界

自动化 Python 集成测试和第一方 JS 语法检查不能证明移动端动画视觉表现、网络延迟容忍度以及真机用户体验完全符合预期。公网部署、性能压测、用户测试和浏览器端到端检查仍需补充。

### 下一阶段建议

可发展「万物任务链」：抽中一种食物后，推荐关联的公开博物馆菜谱／历史藏品；或将一次连续决策串成**吃什么 → 去哪玩 → 看什么 → 研究一件奇物**，但不应将非公开源数据或者虚构的线下店铺当成实时有效推荐。
