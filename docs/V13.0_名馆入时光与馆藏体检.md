# 万物博物馆 V13.0：名馆入时光 · 私人馆藏体检

## 开发目标

过去 V12 世界时间长河只展示网站用户发布的展品，而 V5 的精选世界名馆（17 条来源明确的机构藏品）属于独立目录。这导致新注册、无人发布时，时间长河可能全部空白。V13 在原来「万物时光」中加入**机构来源子展区**，而不是冒充用户发帖或增加重复导航。

## 世界名馆时间长河

- 数据：复用 `world_museums.SEEDS` 及其异步官方 API 丰富结果（The Met / AIC / CMA），不制造虚假的古生物化石或实时科技藏品。
- API：`GET /api/curation/museum-eras`。返回 `eras[]`（与 V12 的时代标签一致）、`institutions`、`categories`、`source`、`notice`。
- 时间：仅对明确年份、公元前年份和世纪标法进行保守识别；跨过时代区间的年代范围标记为「跨越多个时期」；不能识别的标为「时间不详」。年份区间不会假装是精确日期。
- 版权：只有原馆公开接口将图像明确标记为开放访问时才向前端发送 `image_url`。未核实显示文字占位，不默认传播图片。
- 发布权：机构目录与用户公开展品分别计数，机构作品可收藏到个人馆中（默认私密），但不注入用户动态表。
- 时间缺口：这 17 件作品多数在历史文明时代。如果某个时代没有作品就明确留空、提供外部探索入口，不编造“亿年前”的典藏。

## 私人藏品体检

- API：`GET /api/curation/me/quality`（登录必需）。数据仅包含当前账号的 500 件最近修改展品。
- 规则：查看描述、来源、封面、领域/细分类、时代、时间依据、年代原文是否缺失，返回分项具体建议；不进行鉴定真伪，不强迫填充不存在的年代。
- 前端：复用 V12 的「私人世界星图」，展开「馆藏体检」卡片，按需点击编辑既有展品，不新增第二套发布流程。
- 权限：不返回别人的私密收藏，不进行后台无同意的内容更改或分享。

## 验证

`PYTHONPATH=. python -m pytest -q tests/test_curation_v13.py`

全项目：`PYTHONPATH=. python -m pytest -q tests`。

前端：`node --check static/curation.js`；以及 `node --check static/cosmos.js`。

在真实后端浏览器中检查：时代切换、图像加载许可、登录收藏、私人质量列表与编辑、手机端布局。

## 后续重点

要真正填满“亿年前—此刻”的时间轴，必须建立来源可追溯的多机构结构化数据导入，优先自然史、地质、天文学、工业科技和计算机史。必须先核对机构 API 的合法使用方式、年份单位（BCE / CE / 地质年代）、版权、更新机制和数据质量，而不是批量爬取后未经审核展示。
