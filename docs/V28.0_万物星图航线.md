# 万物博物馆 V28.0｜万物星图航线

**让已经保存的个人关联，真正变成可以一步步走的探索旅途。**

## 1. 功能

在「✧ 万物星图」页面底部新增「🌠 万物星图航线」。用户选择两颗目前可用的星点（包括真实馆藏或自己的想法），即可查看是否存在由自己保存的连线组成的最短步数路径。

- **路径预览**：后端对个人持久化连线构造无向图，以 BFS 找到最少连线步数的路径；候选线索、自动标签匹配与跨账号连线不参与寻路。
- **逐站查看理由**：每一段显示用户原先选择的关系类型与亲自记录的解释。界面绝不把路线当成核验的历史事实或科学因果。
- **主动保存航线**：用户为预览成功的路线命名，保存自己的出发星点和目标星点；不保存展示时用到的第三方藏品标题或旧路径快照。
- **私人探索记录**：每个当前可达节点都可以自行标记 / 取消标记「已探索」，并显示该条航线的进度。平台不核验实际到访。
- **动态重计算**：添加或删除连线后，已保存航线下次访问时根据最新真实图重算。路线断开时，显示「航线暂不可用」，**不**伪造路径。
- **默认仅本人可见**：访问、保存、标记、删除均需要登录和用户身份隔离；不自动公开分享路线与进度。

### 例子

星图内有人主动保存：

米线 ——「关联想法」—— 云南饮食文化 ——「历史脉络」—— 茶马古道 ——「个人联想」—— 古代贸易

选择「米线」作为起点、「古代贸易」作为终点，系统会沿现存连线显示四颗星的航线及每段原始理由。即使某两个节点拥有相同的标签，**如果还没有明确保存连线，它们之间就不可自动穿越**。

## 2. 数据模型

`constellation_voyages`：用户 ID、起点节点 ID、终点节点 ID、用户自定义航线名称、创建时间。两个端点均使用级联外键指向 V27 的星图节点。

`constellation_voyage_checkpoints`：航线 ID、星点 ID、用户自行标记的时间；对航线和星点分别使用级联外键，防止悬挂记录。

**不新增任何第三方馆藏标题快照。** 用户自行输入的航线名称为私人数据，在路线断开或相关原始来源撤回后，API 不回传该名称。

## 3. 隐私与真实性约束

- 复用 V27 `graph_payload` 的实时访问控制，包括普通私人展品、玄幻世界、创作工坊和沙盒作品撤回场景；不可用的星点及其边从航线搜索中剔除。
- 中间节点被撤回公开时，不返回旧路线中的任一站名、关系说明或用户给航线取的名称。已标记的私人进度不再算有效路线进度。
- 原始数据源恢复可访问后，航线会重新寻找当前路径；只有仍在当前路径上的私人打卡才会显示为有效。
- 路径只表示**用户主动保存的关联**，不是系统认定的客观知识链；暂时不支持公开分享或 AI 猜测捷径。
- 单用户最大保存 20 条路线，路径规模由 V27 星图的最多 80 节点 / 400 连线自然约束。

## 4. API

| 路径 | 功能 |
|---|---|
| `POST /api/constellation/voyages/preview` | 用起终点 ID 预览当前可达的真实用户连线路径 |
| `GET /api/constellation/voyages` | 列出本人的已保存航线及实时状态 |
| `POST /api/constellation/voyages` | 保存一条当前确实连通的航线 |
| `GET /api/constellation/voyages/{id}` | 获取某条自己的动态航线 |
| `PUT /api/constellation/voyages/{id}/checkpoints/{node_id}` | 自行标记一个当前路径上的节点 |
| `DELETE /api/constellation/voyages/{id}/checkpoints/{node_id}` | 撤销个人标记 |
| `DELETE /api/constellation/voyages/{id}` | 删除私人航线及标记，不影响星图节点或连线 |

## 5. 实现与测试

- 后端：`constellation_voyages.py`，复用 `constellation_api.py` 的授权图视图。
- 页面：`static/voyages.js`、`static/voyages.css`，嵌在 V27 万物星图中，不引入付费或第三方可视化 SDK。
- 验收：`tests/test_constellation_v28.py`，覆盖登录隔离、手动连线构路、最短路径、进度撤销、边删除断路、展品撤回、跨用户防护、页面加载。

**已知边界**：BFS 最少步数并不等于知识质量最优；节点与边数据量当前按 V27 上限控制。真实移动端浏览器端到端验证与生产规模下的使用性能，仍需单独验收。
