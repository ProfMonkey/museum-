# 万物博物馆 Wonder Atlas
## 13 项特色工程与顺序开发路线图（V2.0）

**日期：2026 年 10 月 25 日**  
**项目定位：** 一个允许任何人收藏现实与互联网奇物、建立个人世界、参观他人的展厅，并沿着事物之间的联系持续探索的开放式博物馆。  
**这份文件的用途：** 统一产品边界、说明 7 项已选定的特色工程、补充 6 项新工程，并明确依赖、开发顺序与验收标准。**这里是方案与执行计划，不代表下述功能已全部开发。**

> **一句话体验：** 发现一件有趣的东西 → 存进自己的世界 → 给它赋予意义 → 与其他事物建立连接 → 意外走入别人的世界。
>
> **设计原则：** “收藏”是入口，“探索”是动力，“创造”是长期价值，“猴子”提供有记忆点的趣味；不靠重复签到、虚假积分或刻意堆功能维持活跃。

---

# 一、先看现状：避免把已经做过的东西重做一遍

现有 **V1.0 全功能交互版** 是一个浏览器本地原型，已有个人博物馆、奇物广场的演示、自由布展、沉浸参观、奇遇航线、关系图、探索足迹、搜索筛选、收藏编辑、评论/关注等本地交互、成长展示、数据导入导出，以及浏览器收藏扩展和 PostgreSQL **数据库设计草案**。这些可作为后续工程的产品与交互基础。

**尚未等同于正式上线能力：** 真实注册与认证、服务器持久化、多人之间同步、云端图片存储、实时协作、审核后台、真实关系推荐、可验证来源与完善的隐私权限，均需后端和正式工程实现。**不要把本地模拟的“别人上传”“评论”“举报”标记成已联网完成。**

**与桌面猴项目的关系：** 之前规划过独立的 **ProfMonkey Desktop**（透明桌面宠物、移动物理、状态机、香蕉事故等）。网站内的猴子是**新增集成工程**，可复用角色、美术与行为概念，但**浏览器内的小猴≠能够随意跨越整个 Windows 桌面的桌宠**。真正的全桌面活动需要另行安装桌面程序，不能靠普通网页直接实现。

# 二、工程总览：7 项确定加入 + 6 项新提案

| 编号 | 工程 | 用户最直观的体验 | 优先级 | 复杂度 | 与现有能力的区别 |
|---|---|---|---|---|---|
| E01 | 万物虫洞 | 从一件展品穿越到另一位用户的世界 | S | 中高 | 从“关系图可看”升级为“关系可走、可解释” |
| E02 | 奇物悬案 | 大家协作查明未知物品与离奇现象 | S | 中 | 是持续核验的悬案档案，不是普通评论区 |
| E03 | 一物多界 | 同一物件呈现不同人的解释和故事 | S | 中高 | 共享物件本体，但观点独立保存 |
| E04 | 时间博物馆 | 沿时间轴看一件事物的变化 | A | 中 | 是可追溯时间版本，不是普通创建日期 |
| E05 | 交互式展览 | 展品之间形成分支叙事、选择和结局 | A | 中高 | 从拖拽布展升级为流程与情节编辑 |
| E06 | 现实世界博物馆 | 发现一座城市、校园里的奇物 | A | 中高 | 位置、路线、现场验证与线上展品相连 |
| E07 | ProfMonkey 网站活体猴 | 猴子在网页上爬、躲、睡、捣乱和带路 | S | 中 | 品牌化交互层，不是一般聊天机器人 |
| E08 | 奇物接力 | 由不同用户共同接成“万物故事链” | A | 中 | 人为共同创作；不同于虫洞自动导航 |
| E09 | 猴子馆长 | 一只会介绍藏品、串展与提策展建议的猴子 | A | 中 | 是叙事助手；不替代 E07 的桌宠行为 |
| E10 | 活展品实验室 | 展品可以被操作、模拟、玩起来 | B | 高 | 从静态图文到可交互作品/科学演示 |
| E11 | 同行参观 | 多人同步逛一个馆，现场一起发现 | B | 高 | 是同一时刻的共同体验，不只是关注评论 |
| E12 | 奇物来源护照 | 清楚知道展品从哪里来、有什么证据 | S | 中 | 处理来源可信性、授权与修订历史 |
| E13 | 世界指纹 | 每个人的馆藏形成独特的兴趣星图 | A | 中 | 将馆藏主题结构可视化，不是排行榜 |

**S / A / B 代表实施优先级，不代表立刻同时开发。** 13 项工程属于同一个产品下的工作流，不需要建立 13 套重复的用户系统、评论系统或数据库。

# 三、已确定的 7 项特色工程（E01–E07）

## E01｜万物虫洞：让关联真正变成旅程

**核心体验：** 用户从「打字机」出发，经过「机械键盘—计算机—编码—古代文字」，穿越不同馆主的世界。每次跳转显示**为什么有关联**，不是无理由的随机推荐。

**功能清单：**
- 展品页增加「开启虫洞」，显示 2–5 个有解释的下一站；关系类型如「同一主题、相似用途、历史演化、互相引用、观点冲突」。
- 地图支持跨馆跳转；提供步数、当前路径、上一步与回到起点。
- 用户可收藏整段旅程，生成可公开分享的“奇遇路线卡”，允许别人复走。
- 「从 A 到 B」挑战：尝试用不超过若干次跳转连接两件展品；无法连接要明确提示，不编造关系。

**工程任务：** 图数据模型 `exhibit_relations`、关系证据/解释字段、带边过滤的图遍历、推荐排序、访问权限检查、路线持久化与分享链接。

**验收：** 连续 10 次跳转不出现死链接或越权私密展品；每条虫洞边可查看关联原因；用户能保存并复走同一条路径。

## E02｜奇物悬案：把求知欲变成集体探索

**核心体验：** 用户上传不知道用途的奇怪物件，并发起一宗“悬案”。社区提供线索、猜想与证据，最终留下可核验的结论。

**功能清单：**
- 悬案状态：`待解答 → 有线索 → 待核验 → 已解决 / 存争议`。
- 线索与假设分开：照片、来源链接、解释、反例、引用；投票不能直接等同真相。
- 允许标记“目前无法确定”，允许推翻旧结论，保留结论修改记录。
- 展示悬案时间线、贡献者，以及“尚缺少什么证据”。

**工程任务：** `mystery_cases / hypotheses / evidence / case_reviews / status_history`，内容举报、证据校验、权限控制与通知。

**验收：** 可从发起到解决走通完整流程；每次状态变化可追溯；删去一条证据不会悄悄抹掉历史争议。

## E03｜一物多界：保存不同人如何理解同一件东西

**核心体验：** 同一把椅子，可以从设计、历史、人体工程学、情感记忆、艺术等视角被不同用户收藏和解释。

**功能清单：**
- 区分“物件本体（Object）”与“个人解读（Perspective）”；每人可对同一物件写自己的故事与标签。
- 合并建议只提示**可能是同一件物**，须有人工确认；同类物品不应被误合并成同一个实体。
- 物件页展示观点切换、共通点和相互矛盾的说法；观点属于作者，撤回有审计记录。
- 用户可将他人的公开物件收入自己展厅，同时保存自己的注释和布展方式。

**工程任务：** `objects / object_aliases / perspectives / exhibit_object_links`、实体消歧、版权署名、用户可见范围。

**验收：** 两位用户收藏同一对象不会覆盖彼此文本；私密视角不泄露；错误合并可以撤销。

## E04｜时间博物馆：收藏正在变化的世界

**核心体验：** 一家老店、一个街角、一件旧设备，不只有“一次上传”，而是拥有不同年代的多次见证。

**功能清单：**
- 展品可追加不同时点的“见证记录”，包含拍摄时间、描述与证据。
- 时间轴、前后对比滑块、版本差异说明；展示“上传时间”和“事件发生时间”的区别。
- 支持集体补充：不同用户为同一公共物件提供不同时期的照片/资料。
- 可以制作专题馆，例如「正在消失的校园角落」，但不自动宣称未经证实的历史事实。

**工程任务：** `object_events / snapshots / sources`、时区与时间精度、媒体存储、修订记录。

**验收：** 时间顺序正确；早期版本不可被无痕覆盖；一项未经验证的见证被清楚标注为投稿记录。

## E05｜交互式展览：馆长可以创作互动故事

**核心体验：** 用户进入「人类为何收藏没用的东西？」展览，面对三道选择，不同决定通向不同展品与结局。

**功能清单：**
- 节点式展览编辑器：场景/展品/旁白/选择/分支/结局。
- 内置线性导览、分支故事、知识测验三种模板；无需写代码。
- 发布前自动检查孤立节点、死循环、缺失素材与无出口路径。
- 参观者可重玩、分享路径；馆主可以查看匿名汇总的“选择分布”。

**工程任务：** `story_exhibitions / story_nodes / story_edges / story_versions`、草稿/发布、可访问性与移动端导航。

**验收：** 普通用户在可视化界面建立 5 节点 2 分支展览；任何选择都可正常导航；编辑草稿不破坏已发布版本。

## E06｜现实世界博物馆：把城市与校园变成展厅

**核心体验：** 地图里有别人收藏的老招牌、奇特雕塑、历史街角，用户从数字故事走到现实位置。

**功能清单：**
- 公开奇物地图，地图卡片与站内展品互相跳转。
- 「校园/街区奇物漫游」路线，可标注是否适合现场探访。
- 地点准确度分级：公开精确位置 / 模糊到街区 / 不公开位置，默认不采集持续定位。
- 用户现场添加历史对照照片；未经许可不引导进入私人场所或危险位置。

**工程任务：** `places / location_visibility / field_observations / walking_routes`、地图服务、地理检索、安全和侵权举报。

**验收：** 私密位置不会出现在公共 API；位置权限可撤回；手机端地图与展品的双向跳转有效。

## E07｜ProfMonkey 网站活体猴：让品牌真正“活”在页面里

**核心体验：** 一只戴眼镜、系红领带的原创教授猴，在网页边缘散步、爬展柜、打瞌睡；偶尔吃香蕉、扔香蕉皮、自己滑倒，还会对你的收藏做出反应。

**先区分两种产品形态：**
- **A. 网站猴子（本项目必做）**：在网页视口或网站的展柜、卡片、侧边栏上活动。浏览器只能控制自己页面里的角色，不能跨应用爬到 Windows 桌面。
- **B. Windows 桌面猴（独立可选程序）**：沿用 **ProfMonkey Desktop** 的透明窗体、桌面移动、物理与托盘管理；后期由用户**主动安装、授权登录**，才可和网站同步成就或解锁道具。没有桌面程序时，网站所有核心功能仍正常使用。

**网站猴子最少要有：** 待机、走路、转身、爬侧栏、睡觉、醒来、吃香蕉、掉落/滑倒、点击反馈、拖拽复位；支持「安静模式 / 猴山模式 / 关闭」，记住偏好。

**与博物馆的专属联动：**
- 新增藏品：猴子举着放大镜研究一下，随后归还交互焦点。
- 虫洞出发：猴子拉开一扇小门，跳向下一站，提供可跳过的过场。
- 悬案待解：猴子戴侦探帽，点它出现线索摘要，而不是伪造答案。
- 交互展览：猴子可作为可选导览员；用户认真参观时降低捣乱频率。
- 香蕉事故：吃→扔皮→滑倒→举牌甩锅，作为偶发、可关闭的完整短剧；所有道具留在本站渲染层。

**技术边界：** 首版使用网页端 Canvas/DOM/CSS 动画与状态机；优先复用已有角色素材与动作定义，而不是把 Python 桌面引擎直接塞进前端。移动端自动降低频率，尊重系统“减少动态效果”设置，不覆盖输入框、不抢焦点、不监听输入内容。

**验收：** 猴子能连续活动并在页面切换后恢复；交互区域以外不拦截点击；一键关闭立即停止动画；较低性能手机可降级为静态图标；用户无需安装软件即可在网页见到猴子。

# 四、另外新增的 6 项工程（E08–E13）

## E08｜奇物接力：由人共同创作不可预测的故事链

**玩法：** A 发布「一把旧钥匙」→ B 接上「一扇打不开的门」→ C 接上「门后的老式收音机」。每个人必须写一句“为什么这样接”，所有接力链形成可阅读的合作作品。

**为何不与虫洞重复：** E01 是**探索算法与关系导航**；E08 是**用户主动轮流投稿、共同创作**。

**要做：** 发起接力、接续投稿、主题和分支、结束条件、参与署名、举报和精选链。**验收：** 三个不同账号接续完成一条链；任何一环撤回后提示链已变更，保留合理的版本说明。

## E09｜猴子馆长：会讲故事的策展助手

**玩法：** 点击一件展品，猴子可以用「十秒讲清楚」「讲个反常识角度」「帮我安排参观路线」等方式辅助讲解；馆长写展览说明时给出建议。

**为何不与网站活体猴重复：** E07 负责**角色动作与趣味**；E09 负责**知识组织与叙事**，可以独立关闭。

**要做：** 首版用模板 + 展品真实字段组合介绍；二期再选择性使用 AI 生成讲解。生成内容必须标记 AI 辅助，明确来源、允许编辑，不得编造事实或冒充馆主观点。提供配额限制、缓存和降级，**不需要为这个功能提前购买高额 Token**。

**验收：** 无 AI 也可生成可读的导览卡；AI 输出不会覆盖原展品；来源缺失时不说“已证实”。

## E10｜活展品实验室：收藏不只是观看，还能动手

**玩法：** 某个展品是一只钟，游客可以拨动指针；某个展品是机械装置，可以观察齿轮运动；某个展品是一段算法，可以一步步运行并看状态变化。

**要做：** 支持有限的展品类型：互动图解、参数滑块、短动画、模拟器、安全的嵌入演示。先提供平台审核的组件模板，**不要默认执行用户上传的任意 JavaScript**。后续可支持沙箱隔离、资源限额和作品版本。

**验收：** 参观者可以重置实验；错误参数不会让页面崩溃；不可信脚本不能访问登录凭据与其他用户数据。

## E11｜同行参观：和朋友一起逛同一个世界

**玩法：** 用户创建一个临时参观房间，发出邀请，大家同步看到当前展品，发起人可以带路。每个人可以选择自由浏览，随时回到队伍。

**要做：** 邀请链接与临时房间、主持权、同步当前展品/展览节点、在线成员显示、文字讨论、断线恢复、房间自动过期。先做轻量文字和同步视图，不在首版做实时音视频。

**验收：** 3 人在不同浏览器同步参观；一人网络断开后可恢复；主持人无法强制浏览者打开不安全外链。

## E12｜奇物来源护照：每一件藏品都有可核对的出处

**玩法：** 展品右侧有一张“护照”，展示原作者、发现地点或网页来源、拍摄/上传时间、授权许可、更新记录、引用和争议提示。允许区分原创、转载、个人猜想和已核验资料。

**为何重要：** 这是原创内容与互联网转载混合平台的信任基础。**它不是再造一个标签系统。**

**要做：** `provenance_records / source_links / licenses / revisions / dispute_flags`；来源链接检查、作者授权说明、转载与侵权反馈、媒体删除策略。严禁在未经允许时抓取付费内容或绕过访问限制。

**验收：** 一件公开展品能追溯主要来源；作者撤回后有清晰的处理流程；修改原始出处不会无痕发生。

## E13｜世界指纹：每个人的奇物世界都不一样

**玩法：** 系统从用户**允许分析的馆藏**提取主题分布，生成一张可分享的“世界指纹”：有的人偏机械，有的人偏宇宙，有的人偏城市记忆。点击某一区域可以直接进入相关展品。

**要做：** 标签整理、主题聚类、可解释兴趣图、时间趋势、可编辑标签、隐私开关和分享卡；优先采用本地统计或轻量算法，不用“AI 给人格下结论”。

**验收：** 分享卡仅包含用户授权公开的数据；图上的主题能追溯到对应展品；用户可关闭画像和删除派生数据。

# 五、把 13 项工程连成一个产品，而不是 13 个孤岛

## 5.1 三条最能体现特色的完整体验路线

**路线 A｜探索：** 在奇物广场看到「旧打字机」→ E12 查看来源 → E03 阅读不同人的解释 → E01 打开虫洞 → 穿越到另一个馆主的奇物 → E07 猴子陪同导航 → 收藏路线或接入 E08 接力。

**路线 B｜协作：** 拍下一件未知小机器 → E02 发起悬案 → 社区提交证据 → E12 给结论附出处 → E04 记录后来如何被识别与使用 → E05 将整个发现过程编成互动展览。

**路线 C｜共创：** 整理校园老物件 → E06 标注可公开的位置 → E04 添加今昔对比 → E05 制作校园故事展 → E11 邀请朋友一起参观 → E13 将这些馆藏汇成专属世界指纹。

## 5.2 重复模块合并原则

- **只有一套**用户账号、角色权限、馆藏/媒体存储、标签、评论、点赞、关注、搜索、举报、通知和公开/私密策略。
- “虫洞、接力、关系图”共用**关系数据基础**，但各自保留导航路线、人工接力、展示投影等业务定义。
- “悬案、来源护照、一物多界”共用**证据/引用/作者标识**，但不把「谁说了什么」误当成「事实已证实」。
- “时间博物馆、展览版本、来源记录”共用**版本与事件审计基础**，不重复写一套时间轴框架。
- “网站猴子、猴子馆长、Windows 桌宠”共享**品牌素材和有限的事件约定**，但运行环境和权限必须分别实现。

## 5.3 推荐的业务实体（仅逻辑模型，不是最终迁移脚本）

| 基础域 | 主要实体 | 供哪些工程复用 |
|---|---|---|
| 用户与权限 | User、Profile、Follow、Visibility、Role | 所有工程 |
| 收藏与媒资 | Object、Exhibit、Collection、Gallery、MediaAsset | E01–E13 |
| 观点与证据 | Perspective、Source、License、Evidence、Revision | E02、E03、E04、E12 |
| 关系与旅程 | Relation、RelationExplanation、Route、RelayChain | E01、E08、E13 |
| 时间与空间 | ObjectEvent、Place、Observation、RouteStop | E04、E06 |
| 展览与会话 | Exhibition、StoryNode、StoryEdge、TourRoom、Presence | E05、E11 |
| 趣味与助手 | MonkeySettings、MonkeyEvent、GuideDraft | E07、E09 |
| 社区治理 | Comment、Report、ModerationAction、Notification | 所有公开互动 |

**尤其注意：** 共享的 Object（物件本体）不等于 User 的 Exhibit（个人收藏条目）；一件物可以有多人收藏、多种解释、多份证据。这个拆分决定了 E01/E03/E04 能否长久扩展。

# 六、顺序开发：按依赖分五个阶段推进

## G0｜整顿 V1 原型与共同底座（先做）

**交付：** 整理目录，拆分 CSS、页面组件和 JavaScript；建立前后端项目、测试和持续集成；接通 PostgreSQL；制定对象/展品/用户模型；完成登录、媒体上传、展品真实 CRUD 与权限。

**门禁：** 两个真实账号能独立注册并互相浏览公开展品；私密展品无论从列表、搜索还是直接 URL 都无法越权读取；不丢失原 V1 的核心体验。

## G1｜先实现产品差异化的三个核心（优先形成可展示版本）

**实施顺序：** `E12 来源护照（基础版） → E03 一物多界 → E01 万物虫洞 → E07 网页活体猴（轻量版）`。

**门禁：** 两个人能为同一物件留下不同解读；虫洞可解释且可以跨馆跳转；猴子可关闭、不打断正常操作；展品来源字段清晰。

## G2｜让社区真正产生内容与合作

**实施顺序：** `E02 奇物悬案 → E08 奇物接力 → E04 时间博物馆`。

**门禁：** 一宗悬案从发起、收集证据到核验有完整记录；三人完成接力链；同一物件至少有两个可核对的历史时点。

## G3｜从收藏平台升级为可创造的世界

**实施顺序：** `E05 交互式展览 → E06 现实世界博物馆 → E13 世界指纹 → E09 猴子馆长`。

**门禁：** 不会编程的用户可创建分支展览；地图遵循位置保护；画像可关闭；不用 AI 付费 API 时核心导览也能运行。

## G4｜体验增强与发布质量

**实施顺序：** `E11 同行参观 → E10 活展品实验室 → Windows 桌宠可选联动`。

**门禁：** 多人实时会话可恢复；交互组件安全隔离；桌宠不安装也不影响网页，安装后也不会偷偷访问桌面内容。

> **阶段含义：** G0 是生存线；G1 是产品差异化；G2–G3 是内容与社区成长；G4 是高级体验。功能都进入路线图，但不建议“一口气同时写完”。

# 七、代码工程与成本控制建议

**推荐开发方式：** 单仓库或清晰的前后端双仓库；前端 React + TypeScript，后端使用熟悉且维护成本可控的框架（可选 Node.js/NestJS），数据库 PostgreSQL，图片与附件使用对象存储；实时协作在 E11 才加入 WebSocket。技术选择可在 G0 根据实际熟悉程度调整。

**建议目录结构：**

```text
wonder-atlas/
├─ apps/
│  ├─ web/                  # 网页前端、活体猴、展览编辑器
│  ├─ api/                  # 账号、展品、证据、虫洞、社区等 API
│  └─ desktop-bridge/       # 后期可选；没有也不影响网页
├─ packages/
│  ├─ shared-types/         # 共享类型与 API 契约
│  ├─ design-system/        # 通用卡片、导航、弹窗、主题
│  ├─ graph-domain/         # 关系、路线、接力公共类型
│  └─ monkey-assets/        # 素材与事件清单
├─ database/
│  ├─ migrations/
│  └─ seeds/
├─ tests/
├─ docs/
└─ README.md
```

**花钱原则：** 优先复用现有订阅、免费额度和开源工具；先用确定性算法实现“关系解释”“主题指纹”“导览模板”，只有确实能提升体验且效果经过测试后，再引入按量计费的 AI。使用缓存、任务级上下文与调用限额，避免每次修改都让模型重读整套代码。

**行数原则：** 学校的 23,000 行要求应单独统计：自己维护的源文件、测试、SQL 迁移等按老师指定口径计数；不把第三方依赖、构建产物、自动生成文件或一行拆成十行当作实际工程贡献。最终以**功能可用、可验证、可维护**作为内部质量目标。

**安全与运营底线：** 私密馆藏不能误入公开搜索/推荐/虫洞；必须有版权和举报流程；陌生人投稿要有审核与限流；不主动暴露精确地理位置；猴子不读取键盘内容、不控制真实鼠标；任何 AI 生成内容都需标注且可纠错。

# 八、最小验收清单与下一轮开发任务

## 8.1 正式演示必须能够完成的 10 个动作

1. 两个独立账号完成注册、登录与注销；同一个账户多设备可读到相同公开馆藏。
2. A 创建物件与展品，上传图片、选择公开范围，B 能看公开内容而不能看私密内容。
3. B 给同一物件写不同的个人解读，A 的内容没有被覆盖。
4. 打开某件展品的来源护照，看到创建者、来源与修改记录。
5. 从一件展品跨馆穿越三次，并看到每条虫洞的原因。
6. 网页猴子完成一段短动作与香蕉事故，随时能暂停和关闭。
7. 发起悬案、提交证据、更新核验状态且历史可追溯。
8. 三位用户完成一条奇物接力，并可分享链路。
9. 创建一条拥有至少两个分支结局的互动展览，移动端可参观。
10. 创建今昔时间线，公开版不显示未授权的地理位置。

## 8.2 从现在开始的第一批可执行任务（建议开成 GitHub Issues）

- **WA-001｜原型盘点：** 把 V1 的所有页面、交互、数据字段归类为“可复用 / 本地模拟 / 必须重写”，防止重复劳动。
- **WA-002｜核心实体契约：** 明确 `Object ≠ Exhibit ≠ Perspective`，确定唯一 ID、公开/私密权限与生命周期。
- **WA-003｜真实联网最小闭环：** 账号、展品 CRUD、图片上传、公开浏览、数据持久化与最小权限测试。
- **WA-004｜来源护照基础版：** 创建来源字段、作者署名与修订日志。
- **WA-005｜跨馆关系与虫洞：** 可解释边、路径导航、权限过滤和路线分享。
- **WA-006｜网页猴子第一版：** 统一原创素材、动画状态机、爬行/待机/睡觉/香蕉事故、安静/关闭开关。
- **WA-007｜一物多界：** 同物件多用户视角与误合并恢复。
- **WA-008｜端到端验收：** 至少 2 个账号 + 1 次跨馆穿越 + 1 次猴子事件；记录缺陷并修复。

**总体判断：** 最值得先打磨的是 **「一物多界 + 万物虫洞 + ProfMonkey 网页活体猴」**。前两者让内容越来越有价值，后者提供可识别的产品个性。其他工程按路线图逐步加入，不丢，也不机械叠加。
